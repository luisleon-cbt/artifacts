Copies that save you.

Every recovery metric and every site type depends on one thing: a good backup to recover from. But not all backups are alike. A full backup copies everything; an incremental copies only what changed since the last backup; a differential copies everything changed since the last full. Each strikes a different balance between how much you back up and how hard it is to restore. Toggle the three across a week below , then pick a day to restore and watch how many pieces you need.

Network+ Context — Read this first

Objective 3.3 expects you to distinguish the backup types and a few protection concepts. The exam favorites: incremental = changes since the last backup (small backups, but restore needs the full plus every incremental); differential = changes since the last full (bigger each day, but restore needs only the full plus one differential). Add snapshots (point-in-time images) and the 3-2-1 rule (3 copies, 2 media, 1 offsite), and you\u2019ve got the objective.

The trade-off the exam tests

Incremental: smallest, fastest daily backups , but the slowest, most complex restore, because you need the last full plus every incremental since. Differential: backups grow through the week , but restore is simple: the last full plus one differential. Full: biggest daily backups, but the simplest restore of all (just one set). Why 3-2-1 and immutability matter together

The 3-2-1 rule guards against a single point of failure , lose one copy, one medium, or even the whole site, and another copy survives. Immutable backups add a second layer: even if an attacker (or ransomware) reaches your backups, they can\u2019t be changed or deleted for the retention period. A backup you can\u2019t restore from isn\u2019t a backup , so protection strategy matters as much as backup type.

Key terms
Full backup
Copies all selected data every time. Largest backups, but the simplest restore — a single set.
Incremental backup
Copies only what changed since the last backup (of any type). Small, fast backups; restore needs the full plus every incremental since.
Differential backup
Copies everything changed since the last full backup. Grows daily; restore needs only the full plus the latest differential.
Snapshot
A point-in-time image of a system, volume, or VM — often near-instant. Great for fast rollback, but not a replacement for true offsite backups.
3-2-1 rule
Keep 3 copies of data, on 2 different media types, with 1 copy offsite — so no single failure or site loss destroys everything.
Immutable backup
A backup that cannot be modified or deleted for a set retention period, protecting it against ransomware and tampering.
