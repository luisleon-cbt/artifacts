Addresses on demand.

Hand-typing an IP into every device doesn't scale , DHCP leases them out automatically. But there's a catch the exam loves: a DHCP request is a broadcast, and broadcasts don't cross a router. So when your DHCP server sits on one subnet and your clients sit on others, you need a relay , ip helper-address , to forward those requests across. In this lab you'll build two scopes with exclusions and options on a central server, then configure relay on the Miami core so clients in VLAN 10 and VLAN 20 get addresses from a server they can't even broadcast to.

How a device gets an address by itself.

When a client is set to obtain an address automatically, it doesn't know its IP, its gateway, or its DNS server , it doesn't even know who the DHCP server is. It finds out through a four-step exchange, and the server hands back not just an address but a whole bundle of settings. Your job in this lab is to set up that server and then make sure clients on other subnets can reach it.

Network+ Context — Read this first

The Network+ N10-009 exam is vendor-neutral, but the ideas here are universal: a scope (pool) is the range a server leases; exclusions hold back addresses for static/infrastructure use; options push extra settings (gateway, DNS); a lease is how long a client keeps an address; and a relay (ip helper-address) forwards DHCP across a router because the request is a broadcast. Packet Tracer simulates all of this. Focus on the roles, not the exact menu.

DORA — the four-step lease

How a client gets its address

D
Discover , the client broadcasts "is there a DHCP server out there?" (It has no address yet, so it can only broadcast.)
O
Offer , a DHCP server replies with an available address and settings: "you can have 192.168.10.21."
R
Request , the client broadcasts back "I'll take that one," formally requesting the offered address.
A
Acknowledge , the server confirms the lease (gateway, DNS, lease time included). The client is now addressed.
The broadcast problem (why relay exists)

Discover and Request are broadcasts , and a router (or an L3 switch's SVI) does not forward broadcasts between subnets. So if the DHCP server is on VLAN 99 and the client is on VLAN 10, the Discover never reaches the server. A relay on the client's gateway catches that broadcast and forwards it as a unicast to the server, stamping it with the client's subnet (the giaddr) so the server knows which scope to use.

What you'll build
  • A central DHCP server on VLAN 99 with two scopes , one for VLAN 10 (Staff), one for VLAN 20 (Guest).
  • Exclusions that reserve the low addresses (.1\u2013.20) for gateways, servers, and static gear.
  • Options on each scope: the correct default gateway and DNS server.
  • DHCP relay (ip helper-address) on the SW-CORE SVIs for VLAN 10 and VLAN 20.
  • Verification that clients on those subnets lease addresses from the server across the router.

Routing must already work

Relay forwards DHCP over routing, so inter-VLAN routing on SW-CORE must be working first. Confirm the SVIs are up and that a device on VLAN 99 can ping 192.168.10.1 and 192.168.20.1. If routing is broken, fix it before configuring relay , the relayed unicast has to reach the server and the offer has to route back.

Place the DHCP server

Drag a Server onto VLAN 99. Set Config → FastEthernet0 → Static: IP 192.168.99.10, mask 255.255.255.0, gateway 192.168.99.1. Cable it to a VLAN 99 access port.

Place the test clients

Put PC-Staff on a VLAN 10 port (SW-FLOOR1) and PC-Guest on a VLAN 20 port (SW-FLOOR2). Leave both set to DHCP for now , they'll fail to get an address until relay is configured, which is exactly what you'll prove.

Build the scopes, then relay to them.

Three jobs: define two scopes on the server, turn on relay at the core for both client VLANs, and handle the printer reservation. The server work is in its GUI; the relay is two short CLI lines on SW-CORE.

How the server picks the right scope

One server, two scopes , so how does it know a request is for VLAN 10 vs VLAN 20? The relay stamps each forwarded request with the client's subnet (the giaddr, gateway IP address). The server matches that to the scope whose network contains it. That's why a single central server can address many subnets.

Part C · DHCP relay on SW-CORE

This is the heart of the lab. On each client VLAN's SVI, point the relay at the server with ip helper-address. Now the SVI catches the client's broadcast Discover and forwards it as a unicast to 192.168.99.10.

CLI · IOS Concept: ip helper-address turns a DHCP broadcast into a unicast to the server SW-CORE 
SW-CORE> enable
SW-CORE# configure terminal
! relay DHCP for the Staff VLAN to the central server
SW-CORE(config)# interface vlan 10
SW-CORE(config-if)# ip helper-address 192.168.99.10
SW-CORE(config-if)# exit
! relay DHCP for the Guest VLAN to the same server
SW-CORE(config)# interface vlan 20
SW-CORE(config-if)# ip helper-address 192.168.99.10
SW-CORE(config-if)# end
SW-CORE# write memory
[OK]
Part D · The printer reservation

A reservation pins one device to a fixed address every time. The exam expects the concept; the way you implement it depends on the platform.

Packet Tracer scope note — reservations

Packet Tracer's Server DHCP service does not support per-MAC reservations. Implement the printer two practical ways: (1) keep .50 inside the excluded/low range and statically assign 192.168.10.50 on the printer; or (2) if you run DHCP on a Cisco router/L3 switch instead, use a manual binding (shown below). Either way, document the reserved address in your write-up.

CLI · IOS (reference) Concept: a manual binding = a reservation tying one MAC to one address router-based DHCP 
! reservation via a manual binding (IOS DHCP)
R(config)# ip dhcp pool PRINTER
R(dhcp-config)# host 192.168.10.50 255.255.255.0
R(dhcp-config)# client-identifier 01aa.bbcc.ddee.ff
R(dhcp-config)# default-router 192.168.10.1
! the printer's MAC now always receives 192.168.10.50

The proof in one command

On a client, ipconfig /all (or the Desktop IP Config window) shows the leased address, the gateway, the DNS server, and that the address was DHCP-assigned. If a VLAN 10 client shows 192.168.10.x while the only DHCP server lives on VLAN 99, your relay did its job , the request crossed the router and came back.

When clients don't get an address.

DHCP failures have a small set of usual suspects , and the tell-tale sign is almost always an APIPA address (169.254.x.x), which means the client gave up waiting for a DHCP reply and assigned itself.

Client shows a 169.254.x.x (APIPA) address
Symptom
A DHCP client self-assigns 169.254.x.x , no DHCP server answered.
Likely cause
Missing ip helper-address on the client's SVI, the server is down/off, or no scope matches the subnet.
Diagnose
show run interface vlan 10 for the helper; confirm the server's DHCP service is on and a pool covers that subnet.
Fix
Add the helper-address, enable the service, or create the matching scope; renew the client (re-toggle DHCP).
Client gets an address from the wrong subnet
Symptom
A VLAN 10 client receives a 192.168.20.x address (wrong scope).
Likely cause
The helper is on the wrong SVI, or the scope networks/gateways are mismatched so the giaddr selects the wrong pool.
Diagnose
Verify which SVI carries the client and that each scope's network/gateway matches its VLAN.
Fix
Put the correct helper on the correct SVI; align each scope's network and default gateway to its VLAN.
Client has an IP but no gateway or DNS
Symptom
Address leases fine, but the client can't reach other subnets or resolve names.
Likely cause
The scope is missing the default-gateway or DNS option.
Diagnose
ipconfig /all shows blank Default Gateway / DNS Servers.
Fix
Set the gateway and DNS options in the scope, then renew the lease.
Some clients get addresses, others fail
Symptom
New clients can't lease; existing ones are fine.
Likely cause
The scope is exhausted , too few addresses for demand, often worsened by a long lease time holding addresses.
Diagnose
Compare client count to the pool size (max users); review lease duration.
Fix
Widen the scope (more addresses) or shorten the lease so freed addresses return faster.
Packet Tracer scope note

Packet Tracer simulates DHCP and relay faithfully , DORA, scopes, options, ip helper-address, and APIPA fallback all behave as expected. It does not implement per-MAC reservations on the simple Server (use a static IP or router-based binding), and advanced options (option 82, DHCP snooping nuances) are limited. The exam tests the concepts you practiced here, not PT's menu specifics.
