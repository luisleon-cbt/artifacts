128 bits, two halves.

An IPv6 address looks intimidating until you see its structure: the first 64 bits are the network prefix, the last 64 are the interface ID that identifies the host. The prefix tells you the type , a link-local (fe80::), a globally routable global unicast, or a private unique local. And IPv6 hosts can build their own addresses with SLAAC, no server required. Toggle the address types below, watch the interface ID get built from a MAC with EUI-64, then see how SLAAC and DHCPv6 differ.

Network+ Context — Read this first

Objective 3.4 expects you to recognize IPv6 address types by their prefix and know how hosts get addressed. The big three: link-local (fe80::/10, auto, link-only , like IPv4 APIPA), global unicast (2000::/3, routable , like a public IPv4), and unique local (fc00::/7, usually fd00::/8, private , like RFC 1918). Then the autoconfig pair: SLAAC (the host builds its own address from a router advertisement , stateless) vs DHCPv6 (a server assigns and tracks , stateful).

Two ways IPv6 shortens an address

Leading-zero suppression: within a hextet, drop leading zeros , 0db8 becomes db8, 0001 becomes 1. Double colon (::): replace one run of consecutive all-zero hextets with :: , that's why the link-local above collapses its middle zeros. You can use :: only once per address (otherwise it would be ambiguous).

Building the interface ID — EUI-64

From a MAC to the host half.

Where does that interface ID (021a:2bff:fe3c:4d5e) come from? With EUI-64, the host derives it from its 48-bit MAC address in three moves, then flips one bit. Follow the steps.

1
Start with the 48-bit MAC address
00:1A:2B:3C:4D:5E
2
Split it in half (24 bits each)
00:1A:2B  |  3C:4D:5E
3
Insert FFFE in the middle → now 64 bits
00:1A:2B:FF:FE:3C:4D:5E
4
Flip the 7th bit (the Universal/Local bit) of the first byte
00 = 0000 0000 → 0000 0010 = 02
Flipping that one bit changes the first byte from 00 to 02. (It marks the ID as derived, toggling "universally" to "locally" administered.)
✓
Result: the 64-bit interface ID
02:1A:2B:FF:FE:3C:4D:5E  =  021a:2bff:fe3c:4d5e
This is the host half you saw in every address above , combine it with any prefix to form a full IPv6 address.
Spotting an EUI-64 address

The dead giveaway is ff:fe sitting in the middle of the interface ID , that inserted pair is unique to EUI-64. Note: many modern OSes now use randomized interface IDs for privacy instead of EUI-64, but EUI-64 is what the exam tests because it shows the structure.

Getting configured — SLAAC vs DHCPv6

Build it yourself, or ask a server.

A host has its interface ID , now it needs a prefix and to actually configure an address. IPv6 offers two paths. Toggle between them.

The RA flags decide which one

The Router Advertisement carries two flags that tell hosts how to configure: the M (Managed) flag says "use DHCPv6 for your address," and the O (Other) flag says "use SLAAC for the address, but get other settings (like DNS) from DHCPv6." Pure SLAAC has both off; stateful DHCPv6 sets M. This combination is common: SLAAC for the address, stateless DHCPv6 for DNS.

Key terms
Network prefix / interface ID
An IPv6 address splits into the first 64 bits (network prefix) and the last 64 bits (interface ID, identifying the host).
Link-local
fe80::/10. Auto-configured on every IPv6 interface, used only on the local link, never routed. Like IPv4 APIPA.
Global unicast (GUA)
2000::/3. Globally unique and routable on the Internet , the IPv6 equivalent of a public IPv4 address.
Unique local (ULA)
fc00::/7 (usually fd00::/8). Private, site-internal, not Internet-routed. Like RFC 1918 private IPv4.
EUI-64
Builds a 64-bit interface ID from a 48-bit MAC: split it, insert FFFE, and flip the U/L bit. The ff:fe in the middle is the tell.
SLAAC vs DHCPv6
SLAAC: host builds its own address from the RA prefix (stateless). DHCPv6: a server assigns and tracks addresses (stateful).
