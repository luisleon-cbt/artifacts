Change it on purpose.

Most serious outages aren't caused by attackers \u2014 they're caused by a well-meaning admin making a quick, unreviewed change at 4 p.m. on a Friday. Change management exists to stop that: every change is requested, reviewed, approved, implemented in a window, and documented \u2014 with a rollback plan ready if it goes sideways. Its quiet partner is configuration management: knowing what the device is running now, having a backup to restore, and holding a known-good baseline to build from. Walk the change flow below, then see how the three config states relate.

Network+ Context — Read this first

Objective 3.1 covers change management (the request/approval process) and configuration management (production/running, backup, and baseline/golden configs). The exam tests the purpose: change management prevents unauthorized, risky changes and ensures a rollback plan; configuration management means you can always recover a known-good state. Know the difference between the running config (live now), a backup (restore from it), and the baseline/golden config (the approved standard).

Why the rollback plan is non-negotiable

Approval should never be granted without a rollback (back-out) plan \u2014 a documented way to return to the previous known-good state if the change causes problems. This is the direct link between change management and configuration management: rolling back means restoring a good configuration, which only works if you actually have one saved.

Configuration management — three states of "the config"

Running, saved, standard.

"The configuration" actually means three different things, and the exam expects you to keep them straight. The running config is live right now; a backup is a saved copy you restore from; the baseline/golden config is the approved standard you build from. Backup vs baseline — easy to confuse

A backup is "a saved copy of this device's current config, so I can put it back." A baseline/golden config is "the approved standard a device of this role should match." You restore from a backup; you build new devices from \u2014 and compare for drift against \u2014 the baseline.

Key terms
Change management
The process of requesting, reviewing, approving, implementing, and documenting changes so they're controlled rather than ad-hoc.
Rollback / back-out plan
A pre-defined way to return to the previous known-good state if a change fails. Required before approval.
Maintenance window
A scheduled period during which approved changes are implemented to minimize disruption to users.
Running / production config
The configuration currently active on a device. On many devices it lives in volatile memory and is lost on reboot unless saved.
Backup config
A saved copy of a device's configuration, stored off the device, used to restore after failure or a bad change.
Baseline / golden config
The approved standard configuration a device should match — used to build new devices and to detect configuration drift.
