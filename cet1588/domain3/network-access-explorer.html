How you get in, safely.

Each scenario calls for a different architecture: site-to-site VPN, client VPN, SSL portal, SSH, jump box, or out-of-band console. The complete reference.

Domain 3.5 covers the methods used to reach the network from outside, and the methods used by administrators to manage devices. The big categories: VPNs (site-to-site for connecting whole networks, client-to-site for connecting individual users), remote management protocols (SSH, console, RDP), in-band vs out-of-band management (managing through the data path vs through a separate path), jump boxes (single audited entry point), and API access (programmatic management).

Site-to-Site VPN — Connecting Whole Networks
IPSEC SITE-TO-SITE

The standard for office-to-office

A persistent encrypted tunnel between two firewalls or routers. Each end has a public IP. Traffic between the two private networks is encrypted, encapsulated, and sent across the public internet as if the sites were physically connected.

PORTS: UDP 500 (IKE), UDP 4500 (NAT-T), IP protocol 50 (ESP), IP protocol 51 (AH).

IKE — INTERNET KEY EXCHANGE

Two phases negotiate the tunnel

Phase 1: establishes a secure channel between the gateways (authentication, master keys). Two modes: Main (more secure) and Aggressive (faster, less identity protection).
Phase 2: negotiates the actual IPsec Security Associations (the keys used to encrypt user data).

VERSIONS: IKEv1 (legacy) and IKEv2 (modern, simpler, more reliable).

ESP vs AH

What IPsec actually does

ESP (Encapsulating Security Payload): encryption + authentication + integrity. The common choice. IP protocol 50.
AH (Authentication Header): integrity and authentication, no encryption. Rarely used alone in modern deployments. IP protocol 51.

TUNNEL vs TRANSPORT MODE

What gets encapsulated

Tunnel mode: entire original IP packet (header + payload) is encrypted and given a new outer IP header. Used for gateway-to-gateway (site-to-site).
Transport mode: only the payload is encrypted; original IP header preserved. Used for host-to-host end-to-end.

GRE — GENERIC ROUTING ENCAPSULATION

Tunnel without encryption

GRE creates a logical tunnel between two endpoints but does not encrypt. Useful when you need to carry routing protocols, multicast, or non-IP traffic across an IP network. Often combined with IPsec (GRE-over-IPsec) to add encryption.

PROTOCOL: IP protocol 47.

NAT TRAVERSAL (NAT-T)

When your gateway is behind NAT

IPsec doesn't naturally survive NAT (the IP header changes break authentication). NAT-T wraps IPsec inside UDP 4500 packets to traverse NAT devices. Both ends auto-detect NAT during IKE and switch to NAT-T if needed.

Client-to-Site VPN — Connecting Individual Users
IPSEC CLIENT VPN

Native client on the endpoint

An IPsec VPN client (Cisco AnyConnect, FortiClient, native OS clients) on the user's laptop creates an IPsec tunnel back to a corporate VPN concentrator. Strong encryption, mature standards, but can have NAT/firewall traversal issues.

SSL/TLS VPN (CLIENT-BASED)

VPN over TLS — works through firewalls

Uses TLS (TCP 443, same as HTTPS) so it traverses almost any firewall. A small VPN client runs on the user's device. Examples: OpenVPN, Cisco AnyConnect (SSL mode), GlobalProtect, Pulse Secure.

SSL/TLS VPN (CLIENTLESS)

Browser-only access

User browses to a corporate web portal over HTTPS, authenticates, and accesses internal web apps through a reverse proxy. No software install. Limited to web apps and some RDP/SSH via Java/HTML5. Great for kiosks, contractors, BYOD.

FULL vs SPLIT TUNNEL

Where does internet traffic go?

Full tunnel: ALL traffic from the user's device goes through the VPN — including internet browsing. Corporate firewall inspects everything. Better security; uses corporate bandwidth.
Split tunnel: only traffic to corporate networks goes through VPN; internet traffic exits the user's local connection. Faster, less bandwidth, but less corporate visibility.

In-Band vs Out-of-Band Management
IN-BAND

Manage through the data path

SSH into a switch over the same network the switch is forwarding user traffic on. Works fine when the network is healthy — but if the network is down, you can't manage it.

USE WHEN: Routine admin work. Cheap, simple.

OUT-OF-BAND (OOB)

Separate management path

A dedicated management network (or a console server with serial connections, or a cellular modem) reaches devices independently of the data plane. You can still log in even if the production network is broken.

USE WHEN: Mission-critical infrastructure. After-hours emergencies. Initial bring-up.

CONSOLE SERVER

The OOB workhorse

A device with many serial ports, each connected to the console port of a different switch/router. Admin SSHs into the console server (over OOB network or cellular), then connects to any device's console — even if its main network interfaces are dead.

DEDICATED MGMT NIC

Server iLO / iDRAC / BMC

Servers have a separate Lights-Out Management interface (Dell iDRAC, HPE iLO, Supermicro IPMI, generic BMC) on its own NIC. Lets you power-cycle, reinstall, and watch the console of a server that's completely down. Always put these on the OOB management network.

Jump Boxes & Bastion Hosts
WHAT IT IS

The single entry point

A hardened server that's the ONLY path admins use to reach internal infrastructure. They SSH/RDP into the jump box, then from there reach other systems. Direct admin access to internal systems is blocked at the firewall.

WHY USE ONE

Reduce attack surface, get audit trail

One thing to harden, monitor, and audit instead of many. Session recording on the jump box gives complete logs of every admin action. Strong MFA on one box is easier than on dozens.

PROPER HARDENING

Defense in depth

Minimal services running, current patches, MFA required, IP allow-list, session timeout, audit logging, no outbound internet access. Treat the jump box itself as a high-value target.

BASTION HOST

Same concept, different terms

"Bastion host" and "jump box" are often used interchangeably. Cloud platforms (AWS Session Manager, Azure Bastion, GCP IAP) provide managed bastion services so you don't have to run your own.

Common Exam Traps
  • Site-to-site connects networks; client-to-site connects users. Don't confuse them. A branch office uses site-to-site; a remote employee uses client-to-site.
  • Telnet (TCP 23) is plaintext including passwords. Don't propose it as a solution. SSH (TCP 22) replaces it in every modern scenario.
  • SSL VPN runs over TCP 443. Goes through almost any firewall (looks like HTTPS). IPsec is harder to traverse strict firewalls because of its non-TCP/UDP protocols.
  • Tunnel mode is for gateways. Transport mode is for hosts. Site-to-site VPNs use tunnel mode; host-to-host IPsec (rare) uses transport mode.
  • GRE doesn't encrypt. It encapsulates but provides no confidentiality. Use GRE-over-IPsec when you need both routing flexibility and encryption.
  • Split tunnel ≠ less secure VPN. It's a deliberate design choice trading some security visibility for bandwidth and speed. Many orgs use it.
  • Out-of-band is about a separate PATH, not a separate device. The dedicated mgmt NIC, console server, or cellular modem reaches devices via a path independent of the data network.
  • Jump box ≠ firewall. A firewall filters traffic; a jump box is the ONE host admins use to access many other hosts. They serve different purposes.
  • API access (REST over HTTPS) is preferred for automation. Don't screen-scrape CLI output. Use the device's API.

What this teaches

  • The right access method depends on WHO is connecting, not on what feels familiar. A branch office and a remote employee both "need access to the corporate network" — but the architecture is completely different.
  • Encryption isn't free. IPsec is robust but complex; SSL VPN traverses firewalls easily but is heavier per session. The choice depends on the deployment.
  • Out-of-band exists for a reason. When the network is broken, you can't manage it over the network. Plan for this BEFORE you have an outage.
  • Jump boxes scale security, not access. Many admins → one entry point → one place to harden and audit. Don't over-engineer it for a 5-person shop; do invest in it once your team grows.

When to use which

  • Full tunnel is the right default for regulated industries (healthcare, finance, government) and any organization that needs to inspect 100% of user traffic with a centralized security stack (DLP, web filtering, IDS).
  • Split tunnel is the right default for organizations with bandwidth constraints, geographically distributed users, or heavy use of cloud apps (Office 365, Google Workspace) that work better with direct internet access. Microsoft and Google explicitly recommend split tunneling for their cloud services.
  • The compromise: dynamic split tunneling. Some modern VPN products let you specify per-app or per-destination rules. Office 365 goes direct; everything else goes through the tunnel. Best of both worlds.
