The right tool for what you're hunting.

Every monitoring tool sees a different slice of the network. SNMP polls device counters; syslog captures events; NetFlow shows who talked to whom; packet capture shows the bytes themselves; baselines reveal "different from normal." The exam — and your real-world job — depends on knowing which tool answers which question. This artifact teaches you to pick the right one and to recognize what each one's output looks like.

The complete reference.

Network monitoring is layered. SNMP and flow records tell you about counters and conversations over time. Syslog tells you about discrete events. Packet capture shows you the actual bytes. Discovery protocols (LLDP, CDP) show physical neighbor relationships. APIs let you query everything programmatically. Baselines turn raw numbers into "normal vs abnormal." Knowing which tool fits which question is half the exam.

SNMP — Simple Network Management Protocol
HOW IT WORKS

Manager polls agents

A central SNMP manager (e.g., PRTG, SolarWinds, LibreNMS) sends GET requests to SNMP agents on devices. Agents respond with values from their MIB (Management Information Base). Polling typically every 1-5 minutes.

PORTS: UDP 161 (polling), UDP 162 (traps).

POLLING vs TRAPS

Pull vs Push

Polling: manager asks agent "what's the current interface utilization?" on a schedule. Predictable load, but you miss events between polls.

Traps: agent pushes an unsolicited notification to manager when something happens ("interface down!"). Event-driven, no waiting.

VERSIONS

v1 / v2c / v3

SNMPv1: original, plaintext community strings (security disaster).
SNMPv2c: adds bulk operations, still plaintext community strings.
SNMPv3: adds authentication (SHA/MD5) and encryption (AES/DES). Use this in production.

MIB / OID

What you can query

The MIB is the hierarchical database of monitored values. Each value has an OID (Object Identifier) like 1.3.6.1.2.1.2.2.1.10.1. Vendor MIBs add device-specific OIDs on top of standard MIB-II.

Flow Data — Who Talked To Whom

Flow records summarize traffic as conversations: source IP, dest IP, source port, dest port, protocol, packets, bytes, start time, end time. A router or switch exports flow records to a collector. Much smaller than full packet capture but still answers most traffic questions.

Syslog — Event Logging

Syslog is the universal event logging protocol. Devices send messages to a syslog collector with a severity (0-7) and facility (which subsystem). Centralized syslog is essential — without it, every device holds its own logs and correlation is impossible.

SYSLOG TRANSPORT

UDP 514 (traditional)

Classic syslog uses UDP 514. Fast and lightweight but no delivery guarantee. Modern variants: TCP for reliability, TLS for confidentiality (RFC 5425).

SIEM

Security Information & Event Management

A SIEM (Splunk, QRadar, ELK/Wazuh, Microsoft Sentinel) collects logs from many sources, normalizes them, correlates events, and triggers alerts. The syslog server on steroids.

LOG AGGREGATION

One place to look

Centralize logs from every device into a single collector. Without aggregation, every troubleshooting session means SSH'ing to each device — slow and easy to miss correlated events.

LOG RETENTION

How long to keep them

Retention is driven by compliance (PCI: 1 year, HIPAA: 6 years, GDPR: contextual). Hot storage for recent (queryable in seconds), cold storage for archive (queryable in minutes-hours).

Packet Capture & Port Mirroring
PACKET CAPTURE

The deepest view

Capture the actual packet bytes. Tools: Wireshark (GUI), tcpdump (CLI), tshark (CLI Wireshark). Saved as .pcap files. The only tool that shows packet payloads and protocol-level errors.

USE WHEN: Deep protocol issues, application-layer debugging, security forensics.

PORT MIRRORING / SPAN

Copy traffic to an analyzer

Configure a switch to copy traffic from one or more ports to a dedicated "monitor" port where a packet capture device sits. Switched Port Analyzer (Cisco term: SPAN). Remote variant: RSPAN, ERSPAN over IP.

USE WHEN: You need packet capture from a switched network and can't tap inline.

TAP

Test Access Point — hardware

A physical hardware device inserted into a cable run that mirrors all traffic to a monitor port. Lossless (SPAN can drop under load); doesn't impact switch CPU. Used in security forensics and high-throughput monitoring.

CAPTURE VOLUME

Bytes add up fast

A 1 Gbps link at line rate generates ~10 GB/minute of captures. Use capture filters (BPF syntax) to narrow what's saved. Long-term continuous capture is rarely feasible — capture targeted to a problem window.

API Integration — Programmable Monitoring
REST APIs

Query devices via HTTPS

Modern network devices expose REST APIs (often returning JSON) for both reading state and pushing configuration. Cisco DNAC, Meraki, Arista, Juniper — all expose REST. Authenticated with API keys or OAuth tokens.

NETCONF / RESTCONF

Standardized device APIs

NETCONF (IETF RFC 6241) uses YANG data models and XML over SSH/TLS. RESTCONF is the HTTP/JSON variant. Both let you read and write device config programmatically without screen-scraping CLI output.

WEBHOOKS

Push notifications

Monitoring system POSTs to a configured URL when an event fires. Common for chat integrations (Slack, Teams), ticketing (ServiceNow), and orchestration platforms.

AUTOMATION TOOLS

Ansible · Python · Terraform

Use API integration with automation frameworks. Ansible network modules, Python Netmiko/NAPALM/Nornir libraries, and Terraform providers for major vendors all rely on these APIs.

Network Discovery — What's Out There
LLDP

Link Layer Discovery Protocol

IEEE 802.1AB. Open-standard neighbor discovery — switches/routers advertise their identity, capabilities, port info to directly connected devices. show lldp neighbors shows what's on each port.

USE: Vendor-agnostic L2 discovery. Find what's connected to each switch port.

CDP

Cisco Discovery Protocol

Cisco's older proprietary equivalent of LLDP. Works only between Cisco devices (and some compatible Cisco-derived gear). Still common in all-Cisco environments.

USE: All-Cisco shops. For mixed-vendor → LLDP.

SCANNING TOOLS

nmap, network discovery scanners

Active scanning (sends probes) to map subnets, identify hosts, fingerprint OSes, find open ports. nmap -sn 10.0.0.0/24 for host discovery. Often combined with passive flow data for completeness.

NDP (IPv6)

Neighbor Discovery Protocol

IPv6's replacement for ARP plus router discovery. Uses ICMPv6 messages. Provides neighbor reachability, prefix advertisement, and duplicate address detection.

Baselines & Metrics
PERFORMANCE BASELINE

What "normal" looks like

Measured average and range of metrics (CPU, RAM, link utilization, latency) over a representative period — typically 30 days. Deviations from baseline drive alerts and capacity planning.

METRICS TO TRACK

The standard four

Utilization: bandwidth used vs available.
Errors: CRC errors, dropped packets per interface.
Latency: RTT to key destinations.
Availability: uptime percentage.

ANOMALY DETECTION

Alert on the unusual

Tools alert when current value differs significantly from baseline — not just when it exceeds a fixed threshold. Catches "Tuesday at 9am the network is normally quiet but today it's saturated" without manually defining thresholds for every time-of-day.

TRENDING

Growth over time

Long-term graphs (months/years) of key metrics. Used for capacity planning: when do we need to upgrade the WAN link? When does our switch run out of ports?

Common Exam Traps
  • SNMP v3 is the only secure version. v1 and v2c use plaintext community strings. v3 adds authentication and encryption. Production should always be v3.
  • NetFlow shows conversations, not packets. It summarizes flow records (src/dst/port/bytes). Use packet capture (Wireshark/tcpdump) for actual packet contents.
  • Syslog severity 0 is WORST, 7 is least urgent. Lower number = higher severity. Backwards from how you might think.
  • SPAN / port mirror is for getting traffic TO a packet capture device. It's not capture itself; it's how you feed traffic to the capture tool.
  • LLDP is open standard; CDP is Cisco proprietary. Mixed-vendor → LLDP.
  • SNMP traps push from device; polls pull from manager. Direction matters.
  • Baselines exist BEFORE the problem. You can't compare "now" to "normal" if you never measured normal in calm times.
  • SIEM is broader than syslog. SIEMs ingest syslog and other sources (Windows Event Log, NetFlow, app logs) and correlate.

What this teaches

  • The tools see different things. SNMP shows counters over time. Syslog shows discrete events. NetFlow shows conversations. Packet capture shows actual bytes. Discovery shows topology.
  • The first tool you reach for matters. A user complaint about "slow internet" might be a saturated WAN link (NetFlow shows top talkers), a misconfigured DNS (packet capture shows DNS timeouts), or a CPU-pegged firewall (SNMP shows CPU spike). Each tool tells a different story.
  • Recognize the output format. Real exam questions show snippets of syslog, SNMP, or NetFlow output. If you've seen these formats in this lab, you'll recognize them on the test.
