The complete reference.

Domain 3.4 covers the four most important network services running on top of IP: DHCP (dynamic address allocation), DNS (name resolution), time services (NTP and PTP), and the IPv6-specific autoconfiguration mechanisms (SLAAC, NDP, dual-stack). Together these are what make a network usable — without them you'd be manually configuring IPs, typing IP addresses for every URL, and watching every clock drift independently.

DHCP — Dynamic Host Configuration Protocol
THE DORA PROCESS

D · O · R · A

Discover: client broadcasts "anyone got addresses?" (no IP yet, so it can't unicast).
Offer: server replies with an offer of an IP.
Request: client broadcasts "I accept that offer" (so OTHER servers learn their offers were declined).
Ack: server confirms the lease.

PORTS: UDP 67 (server) · UDP 68 (client).

SCOPE

The pool of IPs to hand out

A DHCP scope defines: the subnet, the range of usable IPs, the gateway, DNS servers, lease duration, and any other options. One scope per subnet — multi-scope servers serve multiple subnets via DHCP relay.

RESERVATION

Static-by-MAC

A reservation binds a specific IP to a specific MAC address. The client still uses DHCP (sends DORA) but always gets the same IP. Used for servers, printers, AP — anything that needs a stable IP without manual config on the device.

EXCLUSION

"Do not lease these"

A range within the scope that DHCP will NOT hand out. Used to reserve IPs for statically-configured devices (printers with manual IPs, gateways, monitoring tools) so they don't collide with DHCP leases.

LEASE TIME

How long the IP is yours

Typical defaults: 8 hours to 8 days depending on environment. Short leases (1-4h) for guest Wi-Fi with high churn; long leases (7+ days) for stable corporate networks. Client renews at 50% of lease.

DHCP RELAY

Crossing subnets

DHCP Discover is broadcast — and broadcasts don't cross routers. A DHCP relay (ip helper-address) catches the broadcast on one subnet and forwards it as a unicast to a DHCP server on another subnet, allowing centralized DHCP for multi-subnet networks.

DNS — Domain Name System
RECURSIVE vs AUTHORITATIVE

Two roles

Recursive resolver: follows the lookup chain on the client's behalf (root → TLD → authoritative → answer). Your ISP runs these. So does 8.8.8.8.
Authoritative: holds the actual zone data. The "source of truth" for a specific domain.

FORWARD vs REVERSE

Two directions

Forward zone: name → IP. Most common direction. www.example.com → 93.184.216.34.
Reverse zone: IP → name. Used by mail servers (anti-spam), logging tools, and security software. Stored in in-addr.arpa (IPv4) or ip6.arpa (IPv6).

INTERNAL vs EXTERNAL

Split DNS / split-horizon

Same domain name can resolve to different IPs depending on who's asking. Internal DNS server answers internal queries with internal IPs (10.x); external DNS answers external queries with public IPs. Common pattern for corporate networks.

TTL

Time To Live

Each DNS record has a TTL specifying how long resolvers may cache it. Short TTL (60s-300s) means changes propagate quickly but generates more queries. Long TTL (1h-24h) means less query volume but slower change propagation. Set TTL low BEFORE planned migrations.

DNSSEC

Signed DNS responses

DNSSEC adds cryptographic signatures (RRSIG records) to DNS responses, defending against DNS cache poisoning. Resolvers can validate that responses came from the legitimate authoritative server. Optional but increasingly common.

DOH / DOT

Encrypted DNS

DNS-over-HTTPS (port 443) and DNS-over-TLS (port 853) encrypt the query/response to prevent eavesdropping and tampering. Major browsers and OSes increasingly use these. A concern for enterprises that rely on monitoring DNS for security.

Time Services — NTP and PTP
NTP

Network Time Protocol

UDP 123. Synchronizes clocks across the internet to typically <10ms accuracy. Uses a hierarchical "stratum" system: stratum 0 = reference clocks (atomic, GPS); stratum 1 = directly synced to stratum 0; each level adds latency and trust degradation.

USE WHEN: Every networked device. Logs across systems are useless if clocks aren't synced.

PTP

Precision Time Protocol

UDP 319 (event) and UDP 320 (general). IEEE 1588. Sub-microsecond accuracy via hardware timestamping. Used in financial trading (regulatory requirements), telecom, industrial automation, and scientific instruments.

USE WHEN: Microsecond accuracy needed — financial markets, broadcast, industrial control.

STRATUM

The trust hierarchy

Stratum 0: reference clocks (not on the network).
Stratum 1: primary time servers.
Stratum 2: synced to stratum 1.
...up to stratum 15.
Stratum 16 = unsynchronized.

WHY TIME MATTERS

It's not just clocks

Kerberos authentication tickets are time-limited (default ±5 min). TLS certificates check validity dates. Logs across servers can't be correlated if clocks differ. MFA TOTP codes are time-based. Distributed databases use timestamps for ordering. Bad time = many silent failures.

IPv6 Autoconfiguration — SLAAC, NDP, EUI-64
SLAAC

Stateless Address Autoconfiguration

An IPv6 host can generate its own address from the network prefix (sent by the router in a Router Advertisement) + an interface identifier it generates locally. No DHCP server needed — but no central record either ("stateless").

EUI-64

The interface ID trick

Convert a 48-bit MAC into a 64-bit interface ID by inserting FFFE in the middle and flipping the 7th bit. Predictable from MAC — privacy concern, so modern OSes also generate random IIDs ("privacy addresses").

NDP

Neighbor Discovery Protocol

IPv6's replacement for ARP and ICMP router discovery. Uses ICMPv6 messages: Router Solicitation, Router Advertisement, Neighbor Solicitation, Neighbor Advertisement. Provides address resolution, prefix discovery, duplicate address detection.

DUAL STACK

Run IPv4 AND IPv6 together

A host (or network) runs both protocol stacks simultaneously. Each interface has both an IPv4 address and one or more IPv6 addresses. Apps prefer IPv6 when available, fall back to IPv4. The standard migration path during the IPv6 transition.

DHCPv6

DHCP for IPv6

IPv6 also has DHCP. Two modes: stateful (assigns addresses, like IPv4 DHCP) and stateless (only provides options like DNS, address comes from SLAAC). The router's RA flags (M and O bits) tell hosts which mode to use.

LINK-LOCAL

fe80::/10 addresses

Every IPv6 interface auto-generates a link-local address (fe80::). Used for NDP, router discovery, and on-link communication. Routers never forward link-local traffic. Always present even if no global IPv6 address is configured.

Common Exam Traps
  • DORA is the right order — Discover, Offer, Request, Ack. Don't confuse with TCP's three-way handshake (SYN, SYN-ACK, ACK). DHCP is four steps.
  • DHCP Discover and Request are both BROADCAST. Offer and Ack are unicast (back to the client's MAC). The client has no IP yet during Discover, so it must broadcast.
  • A record = IPv4. AAAA record = IPv6. Easy to confuse. AAAA is "quad-A" because IPv6 is 4× longer than IPv4.
  • CNAME points to another NAME, not an IP. If you need an IP, you need an A or AAAA record at the end of the chain.
  • MX records have a priority number. Lower priority is preferred. 10 mail1 beats 20 mail2.
  • PTR records are in the reverse zone (in-addr.arpa). Required by many mail systems for anti-spam validation.
  • DHCP relay (helper address) is needed for centralized DHCP across subnets. Without it, each subnet needs its own DHCP server (because broadcasts don't cross routers).
  • NTP UDP 123 vs PTP UDP 319/320. Different services, different ports. PTP achieves much better accuracy but requires hardware support.
  • Lower NTP stratum = higher precision/trust. Stratum 1 (primary servers) is better than stratum 5. Stratum 16 means unsynchronized.
  • SLAAC is stateless — no central server records who has which address. DHCPv6 (stateful mode) does keep records, like IPv4 DHCP.

What this teaches

  • DHCP's broadcast/unicast pattern is asymmetric. Client broadcasts (Discover, Request); server unicasts (Offer, Ack). The Request broadcast is what informs OTHER DHCP servers that their offers were declined.
  • DNS resolution iterates through three tiers. Root nameservers → TLD nameservers (.com) → authoritative for the domain. Each tier just answers "ask this next server" until you reach the authoritative tier with the actual data.
  • Caching hides almost all of this. Resolvers cache aggressively — most lookups skip several steps because the answer (or a partial answer like "I know the .com NS") is already cached. The full chain is rare in practice but matters when debugging.
  • Recursive resolution is iterative under the hood. The "recursive" resolver does iterative queries to root → TLD → authoritative. The CLIENT does one recursive query; the resolver does several iterative queries. Confusing terminology — but heavily tested.
