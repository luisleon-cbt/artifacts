Put the office on the air.

Every wired lab so far ended at a switch port. Now we cut the cord. A wireless access point bridges radio signals to your wired network, letting laptops and phones join the same VLANs as wired hosts. But radio is a shared medium with real physics: only certain frequency bands are usable, each band is sliced into channels, and neighboring access points on the same channel interfere with each other. In this lab you'll add an AP to the CBT Miami office, broadcast a named network (SSID), pick the right band and a non-overlapping channel, secure it with WPA2, and connect wireless clients to the existing Staff VLAN.

Radio is a shared medium.

A wired switch gives every port its own private collision-free connection. Wireless is the opposite: every device sharing a channel competes for the same airtime, like people talking in one room. That single fact drives every design decision in wireless networking — which band to use, which channel to sit on, and how to avoid stepping on neighboring access points. The CBT Miami office needs Wi-Fi for staff laptops and phones, and your job is to add it correctly the first time.

Network+ Context — Read this first

The Network+ N10-009 exam is vendor-neutral. You will not be asked to type Cisco commands on test day. Packet Tracer is used here because it lets you actually broadcast an SSID, pick a channel, and watch a client associate — the best way to make abstract radio concepts concrete. Most wireless settings in Packet Tracer are configured through a device's GUI Config screen rather than a command line, which mirrors how real access points and home routers are set up. Focus on what each setting does — SSID, band, channel, encryption — because those concepts are exactly what the exam tests, regardless of vendor.

Band steering

Many dual-band/tri-band APs broadcast the same SSID on multiple bands and use band steering to nudge capable clients onto the less-congested, faster band (typically 5 GHz or 6 GHz) instead of letting everything pile onto 2.4 GHz. The client still sees one network name; the AP decides which band it lands on.

Channels and why 1, 6, 11 matter

Each band is divided into channels. The catch in the 2.4 GHz band: channels are spaced so closely that adjacent channels overlap and interfere. Out of channels 1–11 (in North America), only 1, 6, and 11 don't overlap each other. That's why every well-designed 2.4 GHz deployment uses only those three — neighboring APs are assigned different non-overlapping channels so their signals don't collide.

Success Criteria

By the end of this lab you must demonstrate:

  1. An access point added to the topology and wired into the switch on a VLAN 10 access port.
  2. SSID configured and broadcasting as CBT-Staff.
  3. A specific non-overlapping channel selected (channel 1, 6, or 11) rather than left on "auto" — and you can state why.
  4. WPA2-PSK security enabled on the AP with a passphrase (open networks are never acceptable for staff use).
  5. Two wireless clients (a laptop and a smartphone) configured with the SSID and passphrase.
  6. Both clients associate to the AP and obtain an IP address in the VLAN 10 subnet (192.168.10.x).
  7. Wireless-to-wired connectivity: a wireless client can ping a wired host or its default gateway.
  8. Wireless-to-wireless connectivity: the laptop can ping the smartphone through the AP.
  9. Configuration saved (the .pkt file) with all settings intact.

Add the access point.

You can build on your Miami topology from the 2.2 series, or start a small fresh topology with one switch. Either way you'll add one AP, one laptop, and one smartphone, and give the wireless clients radio cards.

Prepare the workspace

Open your Miami topology (or build a minimal one)

If continuing the series: open your Lab 2.2.x file and Save As Lab-2.3.1-Wireless-Lastname-Firstname.pkt. If starting fresh: place one 2960 switch and (optionally) a DHCP-capable router or server for VLAN 10 addressing.

Confirm a DHCP source for VLAN 10

Wireless clients will request IPs via DHCP. Make sure something hands out 192.168.10.x addresses — either the Layer 3 switch/router SVI with a DHCP pool, or a dedicated server. (You can also assign static IPs to the clients if you prefer.)

Place the wireless devices

Drag an Access Point onto the canvas

From the device tray: Network Devices → Wireless Devices, drag an Access Point (AP-PT). Place it near SW-FLOOR1. Rename it AP-STAFF via Config → Display Name.

Wire the AP to the switch

Use a Copper Straight-Through cable from the AP's Port 0 (the wired Ethernet port, sometimes labeled "Port0/FastEthernet") to a switch access port, e.g., SW-FLOOR1 Fa0/5. This port must be an access port in VLAN 10 so wireless clients land on the Staff VLAN.

Drag a Laptop and a Smartphone

From End Devices: drag a Laptop and a Smartphone (or a second laptop/tablet). Rename them LAPTOP-1 and PHONE-1.

Give the laptop a wireless NIC (if needed)

Laptops in Packet Tracer ship with a wired NIC. To add Wi-Fi: click the laptop → Physical tab → power it off (the red button) → drag the existing wired module out of the slot → drag in a WMP300N (or WPC300N) wireless module → power it back on. Smartphones and tablets already have wireless built in.

Don't forget to power-cycle when swapping modules

Packet Tracer will not let you remove or insert a network module while the device is powered on. Always click the power button to turn the device off first, swap the module, then turn it back on. Forgetting this is the #1 reason students "can't find the wireless option."

Once the AP is wired in and your clients have wireless cards, move to the Configure tab.

Broadcast and secure the SSID.

Wireless settings in Packet Tracer live in each device's Config GUI, not a command line — except the switch port the AP plugs into, which is real CLI. Apply the switch port config first, then the AP, then the clients.

Watch the link turn green

As soon as a client's SSID and security match the AP, Packet Tracer draws a dotted wireless link between them and the radio LED turns green. If the link stays red or never appears, the SSID or passphrase doesn't match — re-check both ends character by character.

Simulator note — bands in Packet Tracer

The basic AP-PT models the 2.4 GHz band with channels 1–11, which is why this lab uses channel 6. Packet Tracer does not fully simulate 5 GHz/6 GHz channel planning or band steering the way real dual-band hardware does — those are exam knowledge covered in the Brief tab. The concepts (more channels, less congestion, shorter range at higher frequencies) are what the N+ exam tests; the hands-on portion here proves the 2.4 GHz channel + SSID + WPA2 workflow.

What "good" looks like
Association vs IP vs reachability — three separate milestones

Wireless troubleshooting follows a chain: first the client associates (radio link, correct SSID + PSK), then it gets an IP (DHCP working over the wireless-to-wired bridge), then it has reachability (ping). If a ping fails, figure out which milestone broke: no green link = association problem; link but 169.254.x.x address = DHCP problem; valid IP but no ping = a Layer 3 / VLAN / gateway problem. Diagnosing in that order is exactly the methodical approach the exam rewards.

When the client won't join.

Seven wireless failure modes. Most "no Wi-Fi" problems are an SSID or security mismatch.

Client never shows a wireless link to the AP
Cause
SSID mismatch (typo or wrong case), or the client has no wireless NIC installed.
Diagnose
Compare the SSID on the client (Config → Wireless0) to the AP (Config → Port 1) character by character. Check the client's Physical tab for a wireless module.
Fix
Correct the SSID to match exactly, or power off the client and install a wireless module (WMP300N).
Wireless link appears briefly, then drops (red)
Cause
Security mismatch — the authentication type or pass phrase differs between client and AP.
Diagnose
Confirm both sides use the same method (WPA2-PSK) and the identical pass phrase. A single wrong character fails association.
Fix
Re-enter the exact pass phrase (CBTwifi2024!) on both AP and client.
Client associates but gets a 169.254.x.x address
Cause
APIPA — the client requested DHCP but got no response. The wireless-to-wired path to the DHCP server is broken, or no DHCP source exists for VLAN 10.
Diagnose
Check the switch port to the AP is in VLAN 10 and up. Verify a DHCP pool/server serves 192.168.10.0/24.
Fix
Place the AP's switch port in VLAN 10, and ensure the DHCP source is reachable. Then renew DHCP on the client.
Client has a valid IP but cannot ping the gateway
Cause
A Layer 3 issue — wrong gateway on the client, or the VLAN 10 SVI/gateway is down. Not a wireless problem at all.
Diagnose
Confirm the client's default gateway matches the VLAN 10 gateway (192.168.10.1) and that the gateway interface is up.
Fix
Correct the gateway, or bring up the VLAN 10 gateway interface. (See Lab 2.2.2 for inter-VLAN gateway setup.)
Wi-Fi is slow / unreliable when neighboring APs exist
Cause
Co-channel or adjacent-channel interference — multiple APs on the same or overlapping 2.4 GHz channels competing for airtime.
Diagnose
Check what channels nearby APs use. Two APs on channel 6 next to each other will contend; an AP on channel 3 overlaps both 1 and 6.
Fix
Assign non-overlapping channels (1, 6, 11) to neighboring APs so their coverage areas don't interfere.
The wireless option is missing from the laptop entirely
Cause
The laptop still has only its wired NIC; no wireless module was installed (and you cannot swap modules while powered on).
Diagnose
Laptop → Physical tab — is a wireless module present in the slot?
Fix
Power off the laptop, remove the wired module, install a WMP300N wireless module, power back on.
Everyone can join the SSID with no password
Cause
The AP authentication is set to Disabled (open network) instead of WPA2-PSK. This is a security failure, not just a config oversight.
Diagnose
AP → Config → Port 1 — check the Authentication setting.
Fix
Set Authentication to WPA2-PSK with a strong pass phrase. Never run an open SSID for staff/corporate access.
