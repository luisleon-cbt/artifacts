PAT at the edge, HSRP for survival.

Two final concepts close out subtopic 2.1. PAT (Port Address Translation) — the form of NAT that lets every device on Miami's 10.10.10.0/24 private LAN share one public IP to reach the internet. And HSRP (Hot Standby Router Protocol) — the FHRP that survives a router failure by letting two physical routers share a single virtual gateway IP. You'll add a second edge router, configure HSRP between them, watch active/standby roles negotiate, then pull the cable on the active router and watch traffic continue without interruption.

The two problems at the edge.

Every previous lab in this series treated 10.10.10.0/24 as if it were routable across the public internet. It isn't. RFC 1918 reserves 10.0.0.0/8 as a private address block — those addresses are dropped at the first ISP-facing router. To reach the internet, Miami's PCs must have their source IP translated to a public address that R-MIAMI legitimately owns. That's PAT.

Then there's a single point of failure: every Miami PC's default gateway is 10.10.10.1. If R-MIAMI dies — power supply fails, cable yanked, IOS crash — every PC on the LAN loses internet access and there's no automatic recovery. The fix is HSRP: add a second router, give both routers a shared virtual IP 10.10.10.254, and configure PCs to use that virtual IP as their gateway. The two routers elect an active and a standby. If the active fails, the standby takes over the virtual IP within seconds and traffic keeps flowing. PCs never know anything happened.

Add R-MIAMI-2 and its connections

Drag a new 2911 router and name it R-MIAMI-2

Place it next to R-MIAMI. Power it off, install an HWIC-2T serial module, then power on. Set the display name to R-MIAMI-2.

Add a third serial module to R-ATLANTA

R-ATLANTA needs a third serial port for the new WAN link to R-MIAMI-2. Power it off, install a second HWIC-2T if needed (or use the free port on the existing module), power back on.

Connect R-MIAMI-2 to the LAN

Copper Straight-Through: R-MIAMI-2 G0/1 ↔ SW-MIA Fa0/3. Both edge routers now share the same broadcast domain — that's required for HSRP to work.

Connect R-MIAMI-2 to R-ATLANTA via serial

Serial DCE: R-ATLANTA S0/0/2 (click first — DCE) ↔ R-MIAMI-2 S0/0/0 (DTE). This gives R-MIAMI-2 its own path to the rest of the network even when R-MIAMI is down.

Connect R-MIAMI-2 to the ISP cloud

Copper Crossover: R-MIAMI-2 G0/0 ↔ ISP G0/1 (or a second port on your Cloud-PT). The ISP must have a second port available; if you used a Cloud-PT, add an interface.

Change PC-M's default gateway

Update PC-M to use the HSRP virtual IP

Click PC-M → Desktop → IP Configuration. Change Default Gateway from 10.10.10.1 to 10.10.10.254. This is the crucial step — the PC no longer points at a specific physical router. It points at a virtual address that will always be answered by whichever router is currently active.

One subtle thing about HSRP topology

Both R-MIAMI and R-MIAMI-2 must be on the same Layer 2 broadcast domain — same VLAN, same switch (or trunked switches). HSRP uses multicast Hello packets (224.0.0.2) sent inside that broadcast domain to elect active/standby. If you accidentally separate them by a router, HSRP will not work and both will think they're active.

Once R-MIAMI-2 is wired in and PC-M's gateway is updated, move to the Configure tab to bring up routing on R-MIAMI-2 and configure HSRP on both edge routers.

Three configuration steps.

(1) Bring up R-MIAMI-2 with interfaces, EIGRP, and PAT. (2) Add PAT and HSRP active config to R-MIAMI. (3) Update R-ATLANTA to peer with the new R-MIAMI-2 over EIGRP.

Configuration · 01 of 04 — new router, full setup R-MIAMI-2 
! ===== R-MIAMI-2 — Second edge router, HSRP standby =====
enable
configure terminal
hostname R-MIAMI-2
no ip domain-lookup

! ----- Interface to ISP (NAT outside) -----
interface GigabitEthernet0/0
 description To ISP - public side
 ip address 203.0.113.6 255.255.255.252
 ip nat outside
 no shutdown

! ----- LAN interface (NAT inside, HSRP standby) -----
interface GigabitEthernet0/1
 description Miami LAN - HSRP standby
 ip address 10.10.10.2 255.255.255.0
 ip nat inside
 ! HSRP group 1 - same virtual IP as R-MIAMI
 standby 1 ip 10.10.10.254
 ! Default priority 100 means R-MIAMI (priority 110) wins active election
 standby 1 priority 100
 ! Preempt is optional on standby - left off here
 no shutdown

! ----- Serial WAN to R-ATLANTA -----
interface Serial0/0/0
 description WAN to R-ATLANTA
 ip address 10.0.13.1 255.255.255.252
 no shutdown

! ----- EIGRP AS 100 - same as R-MIAMI from Lab 2.1.3 -----
router eigrp 100
 no auto-summary
 network 10.10.10.0 0.0.0.255
 network 10.0.13.0  0.0.0.3
 passive-interface GigabitEthernet0/1
exit

! ----- PAT overload config -----
! ACL 1 defines who gets translated (the entire 10.10.10.0/24)
access-list 1 permit 10.10.10.0 0.0.0.255
! Translate any inside source matching ACL 1 to the G0/0 IP, port-overloaded
ip nat inside source list 1 interface GigabitEthernet0/0 overload

! ----- Static default route to ISP (matches R-MIAMI's config) -----
ip route 0.0.0.0 0.0.0.0 203.0.113.5

end
copy running-config startup-config

The HSRP virtual MAC address

HSRP uses a well-known virtual MAC: 0000.0C07.ACxx where xx is the HSRP group number in hex. Group 1 = MAC 0000.0C07.AC01. This is the key to seamless failover — when the active router fails, the standby starts answering ARP for the same virtual IP and sources frames from the same virtual MAC. PCs don't update their ARP cache because the MAC didn't change.

Common syntax confusion

The standby 1 ip 10.10.10.254 command is sometimes mistyped as standby 1 ip 10.10.10.254 255.255.255.0 — Cisco doesn't take a mask there. The mask comes from the interface IP, not the virtual IP.

Expected output R-MIAMI# show ip nat translations 
Pro Inside global         Inside local          Outside local         Outside global
icmp 203.0.113.2:1     10.10.10.10:1         203.0.113.1:1         203.0.113.1:1

Inside local = the private IP as seen on the inside (PC-M's actual 10.10.10.10). Inside global = how that private IP appears to the outside world after translation (R-MIAMI's public 203.0.113.2). The port numbers (:1024, :1) are what makes this PAT instead of plain NAT — every concurrent flow gets a unique source port.

When HSRP or PAT misbehaves.

Seven failure modes that show up in this lab. Match the symptom, apply the fix.

Both routers think they're Active
Cause
HSRP routers cannot see each other's Hello packets. Almost always a Layer 2 problem — different VLANs, wrong switch port, or the link between switches is down.
Diagnose
On both routers: show standby brief. Both show "local" as active and "unknown" as standby. Then on the switch: show vlan brief — confirm both router ports are in the same VLAN.
Fix
Move both router ports into the same VLAN (default is VLAN 1). Confirm with show interface status.
PC-M can ping 10.10.10.1 and 10.10.10.2 but not 10.10.10.254
Cause
HSRP isn't running on one or both routers. Without an active HSRP router, the virtual IP isn't answered by anyone.
Diagnose
show standby brief on both edge routers. If the output is empty, HSRP isn't configured.
Fix
Re-paste the HSRP block from the Configure tab. Verify the standby 1 ip 10.10.10.254 command is under interface G0/1, not somewhere else.
PC-M can't reach the internet but can reach 10.10.20.10
Cause
PAT isn't translating. Either the ACL doesn't match, the inside/outside markings are wrong, or the overload keyword is missing.
Diagnose
show ip nat translations on the active HSRP router. Empty? PAT isn't running. show ip nat statistics shows hits and misses.
Fix
Verify (1) ACL 1 permits 10.10.10.0/24, (2) ip nat inside on G0/1, (3) ip nat outside on G0/0, (4) the ip nat inside source list 1 interface G0/0 overload command exists.
Failover takes much longer than expected (15+ seconds)
Cause
Default HSRP Hello timer is 3 seconds and hold timer is 10 seconds. Failover can take up to 10 seconds before the standby decides the active is dead.
Diagnose
show standby on either router shows current timer values.
Fix
For sub-second failover in production: standby 1 timers msec 200 msec 600 (Hello every 200ms, dead after 600ms). For Network+ you don't need to tune — the default 10 seconds is acceptable. Mention in your write-up that you understand the trade-off.
After bringing R-MIAMI back up, it stays Standby instead of reclaiming Active
Cause
Missing standby 1 preempt command on R-MIAMI. Without preempt, a router will not actively reclaim the role even when it has higher priority.
Diagnose
On R-MIAMI: show standby | include preempt. If empty, preempt is off.
Fix
Under interface G0/1: standby 1 preempt. The 'P' column in show standby brief output should now show 'P'.
NAT translations appear but disappear quickly between pings
Cause
This is the NAT translation timeout. ICMP entries time out after 60 seconds. TCP entries time out after 24 hours. UDP after 5 minutes. Normal behavior.
Diagnose
show ip nat translations verbose — look at the timeout/created fields.
Fix
No fix required — this is correct. If you need persistent translations for testing, run a continuous ping during the screenshot.
PC-M loses ALL connectivity during failover (not just 1-2 pings)
Cause
PAT state is per-router. When the active router fails, the new active has no record of existing translations. Existing TCP sessions break and must reconnect.
Diagnose
Expected behavior — not a bug. ICMP recovers quickly because each ping creates a new translation; long-lived TCP sessions don't.
Fix
For Network+ purposes, document this as a known limitation. In production, you'd use stateful NAT failover (ip nat stateful) which syncs the translation table between routers. Out of scope here.
