Slice one switch into many with VLANs.

A single physical switch normally puts every connected device into one big broadcast domain — every host can ARP for every other host, every broadcast reaches every port. That's a security problem and a performance problem. VLANs (Virtual LANs) let you carve that switch into multiple isolated Layer 2 segments. In this lab you'll configure a Miami office access switch with three user VLANs (Staff, Guest, Voice) and one management VLAN, assign access ports per role, then connect a second access switch via an 802.1Q trunk so VLANs span both switches.

The scenario.

The CBT Miami office is moving from a single flat network to a properly segmented one. The IT director wants every employee category isolated at Layer 2: Staff devices shouldn't see Guest Wi-Fi devices, Voice phones should be on their own VLAN for QoS, and the Management VLAN — used to remotely administer the switches themselves — should be inaccessible from anywhere else. You'll start with a single access switch (SW-FLOOR1) and add a second (SW-FLOOR2) for the second floor. Both switches share the same four VLANs via an 802.1Q trunk link.

Network+ Context — Read this first

The Network+ N10-009 exam is vendor-neutral. You will not be asked to type Cisco commands on test day. So why are we using Packet Tracer with Cisco IOS? Because the most effective way to internalize what a switching concept does is to watch it work in a real environment — and Packet Tracer is the free, industry-standard simulator available to every networking student. The CLI commands in this lab are Cisco's implementation of vendor-neutral concepts the exam tests. Focus on what each command accomplishes, not on memorizing its syntax. Why no default gateways?

Lab 2.2.1 only configures Layer 2 segmentation. PCs in the same VLAN talk to each other directly via the switch — no gateway needed. Lab 2.2.2 will add inter-VLAN routing (via a Layer 3 switch SVI), which is when each VLAN gets a gateway and Staff can talk to Guest (or be deliberately blocked from doing so via ACL).

Success Criteria

By the end of this lab you must demonstrate:

  1. Four VLANs created and named on both switches: 10 Staff, 20 Guest, 30 Voice, 99 Management.
  2. Access ports assigned to the correct VLAN with descriptive port descriptions.
  3. One port configured for both data and voice (port Fa0/3 on SW-FLOOR1) demonstrating the voice VLAN concept.
  4. 802.1Q trunk operational between SW-FLOOR1 Gi0/1 and SW-FLOOR2 Gi0/1, with native VLAN 99 and the allowed-VLAN list explicitly restricted to 10, 20, 30, and 99.
  5. Intra-VLAN, inter-switch connectivity: PC-S1 (Floor 1, VLAN 10) can ping PC-S2 (Floor 2, VLAN 10) across the trunk.
  6. VLAN isolation works: PC-S1 (VLAN 10) cannot ping PC-G1 (VLAN 20) — demonstrating Layer 2 segmentation.
  7. Management SVI (interface VLAN 99) configured on each switch with a unique IP (.1 and .2) so the switch is remotely manageable.
  8. Console/SSH access to each switch is reachable from VLAN 99.
  9. Configurations saved on both switches.

Objective 2.2 explicitly names VLANs, access ports, trunking, 802.1Q, native VLAN, and voice VLAN. Build the topology.

Open a fresh Packet Tracer workspace. You'll place 2 switches, an IP phone, 4 PCs, and draw 8 cables — including one trunk and one access+voice port.

Place the devices

Drag two 2960 switches onto the canvas

From the bottom-left device tray: click Switches, drag 2960 twice. Rename them SW-FLOOR1 (left) and SW-FLOOR2 (right) via Config → Display Name.

Drag four PCs and one IP phone

From End Devices: drag PC four times and IP Phone once. Arrange below the switches. Rename them PC-S1, PC-G1, PHONE-F1 (under SW-FLOOR1) and PC-S2, PC-G2 (under SW-FLOOR2).

Cable the access ports

Connect PCs to access ports with copper straight-through

Use the Copper Straight-Through cable (lightning-bolt icon → solid line):

  • SW-FLOOR1 Fa0/1 ↔ PC-S1 FastEthernet0
  • SW-FLOOR1 Fa0/2 ↔ PC-G1 FastEthernet0
  • SW-FLOOR1 Fa0/3 ↔ PHONE-F1 Switch Port
  • SW-FLOOR2 Fa0/1 ↔ PC-S2 FastEthernet0
  • SW-FLOOR2 Fa0/2 ↔ PC-G2 FastEthernet0

Connect the trunk between switches with copper crossover

SW-FLOOR1 GigabitEthernet0/1 ↔ SW-FLOOR2 GigabitEthernet0/1 using Copper Crossover. (Modern switches auto-MDIX, but using the correct cable is on the Network+ exam and a good habit.)

Assign PC IP addresses

Set static IPs on each PC

Click each PC → Desktop → IP Configuration. Enter the values from the IP plan in the Brief tab. Leave the default gateway blank — this lab is Layer 2 only. Lab 2.2.2 will add gateways.

If your IP phone is a Cisco 7960

The 7960 in Packet Tracer has only one Ethernet port (the "Switch Port"). When the phone is connected to a port configured for both data VLAN 10 and voice VLAN 30, the phone tags its own RTP traffic into VLAN 30 and passes any computer plugged into its second port untagged into VLAN 10. In this lab the phone stands alone — no PC daisy-chained behind it.

Once all devices are placed, cables are drawn, and PCs have IPs, save the file as Lab-2.2.1-VLANs-FirstLast.pkt. Move on to the Configure tab.

Copy-paste-ready CLI blocks.

Two configuration blocks below — one per switch. Apply SW-FLOOR1 first. Each block creates the VLANs, assigns access ports, configures the voice-enabled port, brings up the trunk with the right native VLAN and allowed-VLAN list, and sets up the management SVI.

A quick refresher on the modes

An access port belongs to exactly one VLAN and sends/receives untagged frames. A trunk port carries multiple VLANs simultaneously, tagging each frame with its VLAN ID using 802.1Q. The native VLAN is the one VLAN whose frames are not tagged on a trunk (for compatibility with legacy devices). The allowed VLAN list restricts which VLANs may cross a given trunk.

Configuration · 01 of 02 Concept: VLAN creation · access port assignment · voice VLAN · 802.1Q trunk · management SVI SW-FLOOR1 
! ===== SW-FLOOR1 — Floor 1 access switch =====
enable
configure terminal
hostname SW-FLOOR1
no ip domain-lookup

! ----- Create the four VLANs and name them -----
vlan 10
 name Staff
vlan 20
 name Guest
vlan 30
 name Voice
vlan 99
 name Management
exit

! ----- Configure access ports (one VLAN each, untagged) -----
interface FastEthernet0/1
 description PC-S1 (Staff)
 switchport mode access
 switchport access vlan 10
 no shutdown
exit

interface FastEthernet0/2
 description PC-G1 (Guest)
 switchport mode access
 switchport access vlan 20
 no shutdown
exit

! ----- Voice + data port (phone tags voice into VLAN 30,
!       leaves data untagged in VLAN 10 for any chained PC) -----
interface FastEthernet0/3
 description PHONE-F1 (Voice + Staff data)
 switchport mode access
 switchport access vlan 10
 switchport voice vlan 30
 no shutdown
exit

! ----- 802.1Q trunk to SW-FLOOR2 -----
interface GigabitEthernet0/1
 description Trunk to SW-FLOOR2
 switchport mode trunk
 ! Native VLAN — frames in this VLAN cross the trunk UNTAGGED.
 ! Set it to a non-default value as a security best practice.
 switchport trunk native vlan 99
 ! Restrict the trunk to exactly the VLANs that should cross it
 switchport trunk allowed vlan 10,20,30,99
 no shutdown
exit

! ----- Shut down all unused access ports (security hardening) -----
interface range FastEthernet0/4 - 24
 shutdown
exit

! ----- Management SVI for remote admin -----
interface Vlan99
 description Management
 ip address 192.168.99.1 255.255.255.0
 no shutdown
exit

! ----- Default gateway for the SWITCH ITSELF (not for users) -----
! Needed so the switch can be reached/managed from outside VLAN 99
! once we add a router or L3 switch in Lab 2.2.2 — uncomment then:
! ip default-gateway 192.168.99.254

end

Critical concept: native VLAN mismatch

If the two ends of a trunk disagree on the native VLAN (e.g., one side says 99 and the other says 1), the switches will log a CDP error and frames in the mismatched VLANs may be misdelivered. Native VLAN must match on both trunk endpoints. Network+ tests this directly.

Why shut down unused ports?

An unused, unshutdown switch port in default VLAN 1 is a security risk — anyone who walks in and plugs a laptop into a wall jack gets immediate network access. Shutting unused ports (or assigning them to an unused "black hole" VLAN) is on the N+ exam as a basic hardening practice.

When VLANs don't behave.

Seven failure modes that show up on this lab. Match the symptom, apply the fix.

PC-S1 cannot ping PC-S2 — Staff↔Staff fails across the trunk
Cause
The trunk isn't actually trunking. Likely one side is still in access mode, or the allowed-VLAN list doesn't include VLAN 10.
Diagnose
On both switches: show interfaces trunk. If Gi0/1 is missing or shows mode "static access", it's not trunking. Compare allowed-VLAN lists end-to-end.
Fix
Re-apply switchport mode trunk and switchport trunk allowed vlan 10,20,30,99 on both Gi0/1 interfaces.
PC-S1 CAN ping PC-G1 — VLAN isolation is broken
Cause
PC-S1 and PC-G1 are in the same VLAN. Almost always: the access ports were assigned to the wrong VLAN, or the access ports default to VLAN 1 because switchport access vlan ... wasn't applied.
Diagnose
show vlan brief — verify Fa0/1 is under VLAN 10 and Fa0/2 is under VLAN 20.
Fix
Re-apply the access-VLAN assignment to the problem port. Also confirm switchport mode access (not dynamic) to lock the mode.
CDP keeps logging "native VLAN mismatch" errors
Cause
The two trunk endpoints disagree on the native VLAN. One is set to 99 (per spec); the other is still defaulted to 1 or set to a different number.
Diagnose
show interfaces trunk on both switches — the "Native vlan" column must match.
Fix
Set both sides to switchport trunk native vlan 99.
A new VLAN (e.g., VLAN 40) was added on SW-FLOOR1 but PC traffic in that VLAN doesn't cross the trunk
Cause
The new VLAN isn't in the allowed-VLAN list, OR it's not defined on the other end of the trunk.
Diagnose
show interfaces trunk shows what's allowed. show vlan brief shows what's locally defined.
Fix
On both switches: create the VLAN (vlan 40 / name X) and add it to the trunk allowed list (switchport trunk allowed vlan add 40). The add keyword is important — without it, you'd replace the existing allowed list.
Management ping from SW-FLOOR1 to SW-FLOOR2 fails
Cause
Either the management SVI is missing/shut on the destination switch, or VLAN 99 isn't crossing the trunk.
Diagnose
On the target switch: show ip interface brief | include Vlan99 — should show 192.168.99.2 up/up. Then confirm 99 is in the trunk allowed list.
Fix
Re-create the SVI: interface Vlan99 / ip address 192.168.99.2 255.255.255.0 / no shutdown. Add 99 to the trunk allowed list if missing.
First ping always times out, then the rest succeed
Cause
ARP resolution. The first packet that needs ARP is dropped while the reply is being received — totally normal Cisco behavior.
Diagnose
Run ping a second time. The next 5 succeed.
Fix
No fix needed. Mention it in your lab report so your instructor knows you understand it.
IP phone shows as connected, but voice VLAN is not appearing in the output
Cause
The phone needs CDP or LLDP to learn the voice VLAN from the switch. If CDP is disabled on Fa0/3, the phone defaults to untagged in VLAN 10.
Diagnose
show interfaces Fa0/3 switchport — Voice VLAN: should show 30. show cdp neighbors should list the phone.
Fix
Confirm cdp run is enabled globally (it is by default on Cisco). On the interface: cdp enable. Power-cycle the phone if needed.
