Static routes & the default route.

Three routers, three LAN segments, two WAN links. Your job: type every route by hand so the engineering PC in Miami can reach the file server in Houston. Then add a default route on the edge router so an unknown destination — the public internet — has somewhere to go. By the end of this lab you'll have configured directly-connected interfaces, hand-written static routes with both next-hop and exit-interface syntax, and verified longest-prefix-match behavior with show ip route.

The scenario.

CBT Networks has three branch offices: Miami (HQ), Atlanta, and Houston. Each branch has a LAN connected to a local 2911 router. The routers are linked by two serial WAN connections: Miami↔Atlanta and Atlanta↔Houston. Atlanta sits in the middle as the transit router — every packet from Miami to Houston (and back) crosses Atlanta's CPU.

Network+ Context — Read this first

The Network+ N10-009 exam is vendor-neutral. You will not be asked to type Cisco commands on test day. So why are we using Packet Tracer with Cisco IOS? Because the most effective way to internalize what a routing concept does is to watch it work in a real environment — and Packet Tracer is the free, industry-standard simulator available to every networking student. The CLI commands in this lab are Cisco's implementation of vendor-neutral concepts the exam tests. Focus on what each command accomplishes, not on memorizing its syntax. Each configuration block below is labeled with the underlying Network+ concept it demonstrates.

Your task is to make every device reach every other device using only static routes — no OSPF, no EIGRP, no RIP. You will also add a default route on the Miami edge router pointing toward a simulated ISP, so that traffic destined for any unknown network has somewhere to go.

Success Criteria

By the end of this lab you must demonstrate:

  1. Every interface is up/up — no shutdown, no protocol-down on any link in the topology.
  2. PC-M pings PC-A (across Miami→Atlanta serial link).
  3. PC-M pings PC-H (across both serial links — Miami→Atlanta→Houston).
  4. PC-H pings PC-M in reverse — proving routes exist in both directions.
  5. R-MIAMI's routing table shows at least one route prefixed with S* (the default route) pointing toward the ISP.
  6. R-MIAMI's routing table shows static routes for 10.10.20.0/24 and 10.10.30.0/24.
  7. A traceroute from PC-M to PC-H shows exactly 3 hops: R-MIAMI, R-ATLANTA, R-HOUSTON.
  8. The running-config is saved on every router (copy running-config startup-config).
Why this matters for the exam

N10-009 objective 2.1 explicitly tests static vs dynamic routes, default route, administrative distance, and route selection. This lab gives you direct, hands-on experience with all four. When you see a routing-table question on the exam, you'll have show ip route output memorized because you've stared at it.

Build the topology in Packet Tracer.

Open a fresh Packet Tracer workspace. You'll place 7 devices, draw 8 cables, and assign the IP addresses listed on the Brief tab. Take your time — a wiring mistake here will haunt you in the verify step.

Devices to place

Drag three 2911 routers onto the canvas

From the bottom-left device tray: click Routers, then drag 2911 three times. Rename them by clicking each one → Config tab → Display Name: R-MIAMI, R-ATLANTA, R-HOUSTON. Arrange them left-to-right.

Add the WIC-2T serial modules

The default 2911 has no serial ports. Click each router → Physical tab → power off the device (small switch on the chassis) → drag a HWIC-2T module into an empty slot → power back on. Miami needs one module (1 serial), Atlanta needs one (2 serials), Houston needs one (1 serial).

Drag three 2960 switches

From Switches, drag 2960 three times. Name them SW-MIA, SW-ATL, SW-HOU. Place each switch below its router.

Drag three PCs

From End Devices, drag PC three times. Name them PC-M, PC-A, PC-H. Place each below its switch.

Add a "cloud" or extra router as the ISP

Drag one more 2911 router or a Cloud-PT to the top-left and name it ISP. You won't configure it; it's just a destination to point Miami's default route at.

Cabling

Connect LAN segments with copper straight-through

Click Connections (lightning bolt) → Copper Straight-Through:

  • R-MIAMI G0/1 ↔ SW-MIA Fa0/1
  • SW-MIA Fa0/2 ↔ PC-M FastEthernet0
  • R-ATLANTA G0/1 ↔ SW-ATL Fa0/1
  • SW-ATL Fa0/2 ↔ PC-A FastEthernet0
  • R-HOUSTON G0/1 ↔ SW-HOU Fa0/1
  • SW-HOU Fa0/2 ↔ PC-H FastEthernet0

Connect WAN serial links with serial DCE cable

Use Serial DCE (clock-icon symbol). The router you click first becomes the DCE end — that's important because the DCE provides the clock rate.

  • R-MIAMI S0/0/0 (click first — becomes DCE) ↔ R-ATLANTA S0/0/0 (DTE)
  • R-ATLANTA S0/0/1 (click first — becomes DCE) ↔ R-HOUSTON S0/0/0 (DTE)

Connect Miami to the ISP

R-MIAMI G0/0 ↔ ISP G0/0 (or your Cloud equivalent). Use Copper Crossover for router-to-router Ethernet.

Common setup mistake

If you connect a copper straight-through between two routers (Miami to ISP) instead of a crossover, the link will come up but auto-MDIX may or may not fix it depending on PT version. Use crossover for router-to-router Ethernet and you'll never debug a phantom Layer 1 issue.

Assign PC IP addresses

Configure each PC's IP, mask, and default gateway

Click each PC → Desktop tab → IP Configuration. Enter the values from the IP plan on the Brief tab. Don't forget the default gateway — without it the PC can ping its own router but nothing beyond.

When all 7 devices are placed, all 8 cables are drawn, and all 3 PCs have IPs, save your file as Lab-2.1.1-StaticRouting-FirstLast.pkt. Move on to the Configure tab.

Copy-paste-ready CLI blocks.

Each block below is one router's complete configuration. Click Copy, open that router's CLI tab in Packet Tracer, type enable then configure terminal, paste, and you're done. Lines beginning with ! are comments — they're for you, the router ignores them.

Before you paste

Every CLI session in Packet Tracer should start with enable then configure terminal. The blocks below assume you're already in global config mode.

no ip domain-lookup

! Serial link to Atlanta (Miami is DCE — provides clock rate)
interface Serial0/0/0

 ip address 10.0.12.1 255.255.255.252

! ----- Static routes -----
! To reach Atlanta LAN
ip route 10.10.20.0 255.255.255.0 10.0.12.2
! To reach Houston LAN (recursive lookup through Atlanta serial)
ip route 10.10.30.0 255.255.255.0 10.0.12.2

ip route 10.0.23.0 255.255.255.252 10.0.12.2
! Default route to the ISP — sends all unknown traffic out G0/0
ip route 0.0.0.0 0.0.0.0 203.0.113.1

end

Two ways to write a static route

Next-hop syntax: ip route 10.10.20.0 255.255.255.0 10.0.12.2 — the router does a recursive lookup to find which interface 10.0.12.2 is on. Works on any media.
Exit-interface syntax: ip route 10.10.20.0 255.255.255.0 Serial0/0/0 — skips the recursion, slightly faster. Best on point-to-point serial links. Both are tested on Network+.

Why does R-MIAMI need a route to 10.0.23.0/30?

When a packet sourced from 10.10.10.10 tries to traceroute to PC-H, the Atlanta-Houston serial interfaces will send ICMP TTL-exceeded messages back from their own IPs (10.0.23.1 or 10.0.23.2). If Miami has no route back to that subnet, those messages get dropped and your traceroute shows asterisks. The route ip route 10.0.23.0 255.255.255.252 10.0.12.2 fixes this.

When it doesn't work.

Below are the seven most common failures students hit on this lab. Read the symptom first; if it matches what you're seeing, the cause and fix tell you exactly what to do.

PC-M cannot ping its own default gateway 10.10.10.1
Cause
G0/1 on R-MIAMI is shut down, or the PC's IP/mask/gateway is wrong, or the SW-MIA port is in the wrong VLAN.
Diagnose
On R-MIAMI: show ip interface brief | include GigabitEthernet0/1. On PC-M: ipconfig. Verify both ends.
Fix
R-MIAMI: interface G0/1 → no shutdown. PC: re-enter IP 10.10.10.10/24, gateway 10.10.10.1.
Serial link shows "Serial0/0/0 up, line protocol down"
Cause
Layer 1 is fine but Layer 2 isn't negotiating. Usually missing clock rate on the DCE side, or one router is shutdown.
Diagnose
show controllers Serial0/0/0 — the DCE side will say "DCE V.35, clockrate is …". If clockrate is missing/0, that's your problem.
Fix
On the DCE end: interface S0/0/0 → clock rate 1544000 → no shutdown.
PC-M pings PC-A but fails to ping PC-H
Cause
One of three things: R-ATLANTA has no route back to 10.10.10.0/24, R-ATLANTA has no forward route to 10.10.30.0/24, or R-HOUSTON has no return route to 10.10.10.0/24.
Diagnose
On each router run show ip route and confirm every distant LAN appears as S [1/0] via ….
Fix
Re-paste the static routes block from the Configure tab on whichever router is missing them.
First ping always times out, then the rest succeed
Cause
ARP resolution. Cisco devices send the first packet that needs ARP into the bit bucket while waiting for the reply. This is normal behavior, not a bug.
Diagnose
Run ping a second time — all 5 should succeed.
Fix
No fix needed. Mention this in your lab report so your instructor knows you understand why.
Traceroute shows asterisks for one hop, then succeeds
Cause
An intermediate router has no return route to the source. ICMP TTL-exceeded messages can't get back to PC-M.
Diagnose
If the asterisk hop is the Atlanta-Houston serial subnet (10.0.23.0/30), R-MIAMI is missing a route to that subnet.
Fix
On R-MIAMI: ip route 10.0.23.0 255.255.255.252 10.0.12.2 — already included in the Configure block for exactly this reason.
% Invalid input detected at '^' marker
Cause
You're in the wrong mode for the command. ip route only works in global config. no shutdown only works in interface config. show requires privileged exec.
Diagnose
Look at the prompt: Router> = user, Router# = privileged, Router(config)# = global, Router(config-if)# = interface.
Fix
Type end (or Ctrl-Z) to go all the way back to privileged exec, then re-enter the right mode.
Everything works during the session but fails after reload
Cause
You never saved the running-config. After a reload, the router boots its startup-config — which is still empty.
Diagnose
show startup-config returns "startup-config is not present" or shows an old config.
Fix
In privileged exec: copy running-config startup-config (or shortcut: write memory). Then save the .pkt file too.
