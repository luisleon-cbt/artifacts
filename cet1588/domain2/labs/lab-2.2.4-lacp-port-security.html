Bundle the links, lock the ports.

In Lab 2.2.3, Spanning Tree blocked one of your redundant links to prevent a loop — which kept the network safe but wasted half your bandwidth. Link aggregation fixes that: bundle two or more physical links into one logical channel and STP treats the bundle as a single link, so every cable forwards and you get redundancy. You'll build an aggregated channel with LACP (the open standard) between SW-CORE and an access switch. Then you'll harden the edge with port security — limiting which MAC addresses can use a port and choosing what happens when an unauthorized device plugs in. This is the final lab of the switching series; by the end, the full Miami office topology is complete.

Two problems, two features.

This lab solves two real-world problems that the previous labs surfaced. Problem one: in Lab 2.2.3, STP had to block one of the two links between your switches to prevent a loop — so you paid for two cables but only got the bandwidth of one. Problem two: your access ports are wide open — anyone who unplugs a PC and plugs in their own laptop (or a rogue switch) gets straight onto the corporate VLAN.

Link aggregation (also called EtherChannel, LAG, or port channel) solves the first by bundling multiple physical links into a single logical link. STP sees one link, so there's no loop to block — and traffic is load-balanced across all the member cables. If one cable fails, the channel keeps running on the others. Port security solves the second by restricting which MAC addresses are allowed on a port and defining what the switch does when an unauthorized device appears.

The terminology zoo

Link aggregation goes by many names — and the Network+ exam may use any of them: EtherChannel (Cisco's term), port channel (the interface name), LAG (Link Aggregation Group — common on other vendors), bonding or teaming (on servers), and trunk (confusingly, some vendors call a LAG a "trunk" — but in Cisco-land "trunk" means an 802.1Q VLAN trunk, which is something completely different). They all describe the same idea: multiple physical links acting as one logical link.

Port-security violation modes

Once you tell a port which MAC address(es) are allowed, you must tell it what to do when a different MAC shows up. There are three modes:

Protect
Silent drop

Drops frames from unauthorized MACs. No logging, no counter, no alert. The offending device just silently fails to communicate. Least visibility.

Restrict
Drop + log

Drops unauthorized frames and increments a violation counter and sends an SNMP/syslog alert. The port stays up. Good balance of security and visibility.

Shutdown
Err-disable (default)

Immediately err-disables the entire port on a violation — no traffic at all until an admin manually re-enables it. The default mode, and the most aggressive.

PoE awareness (exam knowledge)

The Network+ exam also expects you to recognize Power over Ethernet standards, even though Packet Tracer doesn't simulate power draw in detail. PoE lets a switch deliver electrical power over the same Ethernet cable that carries data — powering IP phones, wireless access points, and cameras without a separate power adapter:

StandardNamePower at the deviceCommon use
802.3afPoE~12.95 WVoIP phones, basic APs
802.3atPoE+~25.5 WPTZ cameras, dual-radio APs
802.3btPoE++ (Type 3/4)~51–71 WWi-Fi 6 APs, video phones, displays

The Voice VLAN phone you configured back in Lab 2.2.1 would, in a real deployment, draw power from the switch via 802.3af PoE — no wall adapter needed. That's why access switches are often spec'd with a PoE power budget.

Expect both new links to show as "blocking" at first

The instant you connect the second parallel link, STP will block one of them to prevent a loop — exactly what you saw in Lab 2.2.3. That's fine and expected. Aggregation will fix it: once the two links are bundled into a channel, STP sees a single logical link with nothing to block.

The cardinal rule of EtherChannel members

Every physical port in an aggregated channel must have identical settings: same speed, same duplex, same mode (access or trunk), same native VLAN, same allowed-VLAN list. If the member ports disagree on any of these, the channel will not form and the ports may be err-disabled. Configure the channel settings on the logical port-channel interface and they propagate to the members.

Once the second link is in place, move to the Configure tab to bundle them.

Bundle, then lock down.

Three configuration blocks. SW-CORE and SW-FLOOR1 each get the LACP channel config (settings must match). SW-FLOOR1 also gets port security on its access port facing PC-S1.

enable
configure terminal

! ----- Select BOTH member interfaces together -----
interface range GigabitEthernet0/1 - 2
 ! Make them trunks BEFORE channeling so settings match
 switchport trunk encapsulation dot1q

 switchport trunk allowed vlan 10,20,30,99
 ! Bundle into channel-group 1 using LACP.
 ! 'active' = this side actively sends LACP negotiation frames.
 channel-group 1 mode active
 no shutdown
exit

! ----- Configure the logical port-channel interface -----
! Settings here apply to the whole bundle.
interface Port-channel 1

 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,30,99
exit

end

LACP mode pairing — what forms a channel

LACP has two modes: active (sends LACP frames to start negotiation) and passive (only responds). The combinations that work: active + active ✓, active + passive ✓. The combination that does not: passive + passive ✗ (both sides wait, neither initiates). We used active on SW-CORE and passive on SW-FLOOR1 — a valid pairing.

Why sticky MAC is so useful

Manually typing every authorized MAC address would be a nightmare. Sticky learning lets the port learn the MAC of whatever legitimate device is connected right now, then write it permanently into the config. After that, only that exact device works on the port. If someone unplugs the PC and connects a different laptop, the new MAC violates the policy and the violation mode triggers.

When the bundle or lock fails.

Seven failure modes split across aggregation and port security.

Port-channel won't form — members show (I) stand-alone instead of (P)
Cause
Mismatched settings between the two ends, or an invalid LACP mode pairing (passive + passive).
Diagnose
show etherchannel summary on both sides. show run interface Gi0/1 on each member — compare speed, duplex, trunk mode, native VLAN, allowed VLANs.
Fix
Make all member settings identical. Ensure at least one side is mode active. Re-add the members to the channel group.
Both member ports got err-disabled when the second cable was plugged in
Cause
EtherChannel misconfiguration guard. The two links formed a loop before being bundled, or the config differed between members, so STP/EtherChannel err-disabled them.
Diagnose
show interfaces status err-disabled — reason will mention channel-misconfig.
Fix
Fix the member config to match, then shutdown / no shutdown the members (or the port-channel) to clear err-disable.
Channel forms but VLAN traffic doesn't cross it
Cause
The port-channel interface isn't trunking, or its allowed-VLAN list is wrong. Configuring the members but not the logical Po1 interface is a common slip.
Diagnose
show interfaces trunk — is Po1 listed as a trunk with the right VLANs?
Fix
On interface Port-channel 1: set switchport mode trunk, native VLAN 99, and the allowed-VLAN list. These apply to the whole bundle.
Port security won't enable — "Command rejected: ... not an access port"
Cause
Port security can only be applied to a statically configured access port (or a static trunk), not a port left in dynamic/auto mode.
Diagnose
show run interface Fa0/1 — check whether switchport mode access is present.
Fix
First set switchport mode access, then apply the switchport port-security commands.
Port went into err-disabled the moment port security was enabled
Cause
More MACs were already learned on the port than the maximum allows (e.g., a hub or a daisy-chained device behind the PC), and violation mode is shutdown.
Diagnose
show port-security address — count how many MACs the port saw. Compare to the maximum.
Fix
Remove the extra device, raise the maximum if legitimately needed (e.g., a phone + PC = 2), then recover the port with shutdown / no shutdown.
Violation count keeps incrementing but the port stays up
Cause
This is expected behavior in restrict mode — it drops the unauthorized traffic and logs each violation, but does not shut the port. Not a bug.
Diagnose
show port-security interface Fa0/1 shows mode Restrict and a climbing violation count.
Fix
If you want the port disabled on violation instead, change the mode: switchport port-security violation shutdown.
After swapping back to the original PC, the port is still down
Cause
The violation used shutdown mode and err-disabled the port. Reconnecting the right device does not auto-recover an err-disabled port.
Diagnose
show interfaces status err-disabled lists Fa0/1 with reason psecure-violation.
Fix
Manually recover: interface Fa0/1 → shutdown → no shutdown. (Or configure err-disable auto-recovery for psecure-violation.)
