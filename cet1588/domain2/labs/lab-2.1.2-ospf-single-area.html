From static to dynamic.

In Lab 2.1.1 you typed every route by hand. That works for three routers — it falls apart at thirty. OSPF (Open Shortest Path First) is the open-standard link-state protocol that solves this. Each router floods information about its links (not its routes) to every neighbor in the same area. Every router then runs the Dijkstra algorithm on the combined link-state database and computes the shortest path to every destination.

The result: identical reachability to Lab 2.1.1, but the routers — not you — maintain the routing table. When a serial link drops, OSPF reconverges in seconds. When you add a new LAN, you advertise it once and every router learns it automatically.

Topology — same as Lab 2.1.1
What's new in this lab
  • Router IDs (RID) — manually set so they're predictable. R-MIAMI = 1.1.1.1, R-ATLANTA = 2.2.2.2, R-HOUSTON = 3.3.3.3. Without manual RIDs, the router picks the highest IP on any active interface — fine, but unpredictable in labs.
  • OSPF cost — the metric. Calculated as 10⁸ / bandwidth. A 1.544 Mbps T1 link = cost 64. A 100 Mbps FastEthernet = cost 1. Lower cost = more preferred.
  • Neighbor adjacencies — OSPF sends Hello packets every 10 seconds on broadcast links to find neighbors and form an adjacency. You'll see them form in real time.
  • Default route advertisement — R-MIAMI is the edge router. It originates a default route into OSPF so R-ATLANTA and R-HOUSTON learn how to reach the internet without you statically configuring it on each.

Why this matters for the exam

N10-009 objective 2.1 names OSPF explicitly. Expect questions about OSPF area 0, AD = 110, link-state vs distance-vector, and neighbor states. The exam loves the trick question: "OSPF and static both have a route to 10.10.30.0/24 — which wins?" Static (AD = 1) wins over OSPF (AD = 110). This lab burns that into memory.

Strip out the old statics

Remove every static route on all three routers

OSPF and lingering statics will coexist — but the static will always win because of AD. To prove OSPF works on its own, remove the statics first. The Configure tab shows the exact no ip route … commands.

Confirm the routing table is now empty of statics

On each router: show ip route static. The output should say no routes found or just list the gateway-of-last-resort if you left the ISP-pointing default. We'll let OSPF handle that next.

The connectivity break

After removing the statics, connectivity between LANs will fail — that's expected. PC-M still reaches its own subnet but not Atlanta or Houston. Don't panic; that's the empty canvas OSPF will paint on.

Once the statics are gone and you've confirmed the break, move to the Configure tab to bring OSPF up.

Bring up OSPF.

Three configuration blocks below — one per router. Each block removes the old statics first, then enables OSPF with process ID 1, sets a memorable router ID, and advertises every connected network into area 0. Order matters: configure R-ATLANTA last so you can watch its neighbor adjacencies form to both sides in real time.

OSPF network statement syntax

Cisco OSPF uses wildcard masks (inverse of subnet masks), not subnet masks. A /24 (255.255.255.0) is written as 0.0.0.255. A /30 (255.255.255.252) is written as 0.0.0.3. Memorize this — it's the most common syntax error on the exam and in labs.

Configuration · 01 of 03 R-MIAMI 
! ===== R-MIAMI — Edge router, area 0 =====
! Remove the statics from Lab 2.1.1
configure terminal
no ip route 10.10.20.0 255.255.255.0 10.0.12.2
no ip route 10.10.30.0 255.255.255.0 10.0.12.2
no ip route 10.0.23.0 255.255.255.252 10.0.12.2
! Keep the ISP default route — we will redistribute it
! into OSPF in a moment so neighbors learn it dynamically

! ----- Enable OSPF -----
router ospf 1
 ! Hard-set the router ID for predictability
 router-id 1.1.1.1
 ! Advertise the Miami LAN into area 0
 network 10.10.10.0 0.0.0.255 area 0
 ! Advertise the WAN serial subnet into area 0
 network 10.0.12.0 0.0.0.3 area 0
 ! Originate the default route into OSPF so neighbors learn it
 default-information originate
 ! Optional: silence OSPF on the LAN-facing interface (no neighbors live there)
 passive-interface GigabitEthernet0/1
exit
end
copy running-config startup-config

Watch the console messages

As soon as you commit the OSPF config on R-ATLANTA, you'll see real-time console messages:
%OSPF-5-ADJCHG: Process 1, Nbr 1.1.1.1 on Serial0/0/0 from LOADING to FULL, Loading Done
%OSPF-5-ADJCHG: Process 1, Nbr 3.3.3.3 on Serial0/0/1 from LOADING to FULL, Loading Done
Those FULL adjacencies are the green light — neighbors found, link-state databases exchanged, SPF run. Routes are now in the table.

Wildcard mask gotcha

If you write network 10.10.10.0 0.0.255.255 area 0 (wrong — that's /16) instead of 0.0.0.255 (right — /24), OSPF still works but advertises a wider range. On the exam, when you see network + a wildcard, do the math: subtract each octet of the subnet mask from 255. 255.255.255.0 → 0.0.0.255. 255.255.255.252 → 0.0.0.3.

When OSPF won't converge.

Seven failure modes I see students hit on this lab. Match your symptom, then apply the fix.

Neighbor never appears in show ip ospf neighbor
Cause
The serial link is up but OSPF Hellos aren't being exchanged. Almost always because the wildcard mask in the network statement doesn't cover the interface's IP.
Diagnose
show ip ospf interface brief — if the serial isn't listed, OSPF isn't running on it. Also check show running-config | section router ospf and recompute the wildcard.
Fix
Re-enter the network statement with the correct wildcard: network 10.0.12.0 0.0.0.3 area 0.
Neighbor stuck in EXSTART or EXCHANGE state, never reaches FULL
Cause
MTU mismatch between the two interfaces. OSPF refuses to form an adjacency if MTUs differ — protection against fragmenting LSAs.
Diagnose
show ip interface S0/0/0 | include MTU on both ends. Compare.
Fix
Either set MTUs equal, or override with ip ospf mtu-ignore under the interface (acceptable in lab, debatable in production).
Routes learned via OSPF are flapping (appearing and disappearing)
Cause
Duplicate router IDs. Two routers using 1.1.1.1 will fight over LSAs and constantly tear down/rebuild adjacencies.
Diagnose
show ip ospf | include Router ID on each router. Confirm all are unique.
Fix
Change one with router-id x.x.x.x under router ospf 1, then clear ip ospf process to apply.
PC-M can ping PC-A but not PC-H
Cause
R-ATLANTA's network statement for the 10.0.23.0/30 link is missing or wrong. R-ATLANTA forms an adjacency with R-MIAMI but never with R-HOUSTON.
Diagnose
On R-ATLANTA: show ip ospf neighbor. Should show two neighbors, not one.
Fix
Add network 10.0.23.0 0.0.0.3 area 0 under router ospf 1 on R-ATLANTA.
No default route appearing on R-ATLANTA or R-HOUSTON
Cause
R-MIAMI is missing default-information originate, or it has the command but no actual default route in its own table to advertise.
Diagnose
On R-MIAMI: show ip route 0.0.0.0. If empty, your static ip route 0.0.0.0 0.0.0.0 … is missing.
Fix
Confirm the static default exists, then under router ospf 1 add default-information originate.
All routes load but metrics look enormous (e.g. cost 1562 instead of 64)
Cause
Interface bandwidth statement is missing or wrong. Packet Tracer serial defaults to 1544 Kbps, but some images report bandwidth as 64 Kbps until you set it explicitly.
Diagnose
show interfaces Serial0/0/0 | include BW — should show BW 1544 Kbit.
Fix
Under the interface: bandwidth 1544. The bandwidth statement only affects metric calculation, not actual throughput.
OSPF works but a static route is still being used preferentially
Cause
You forgot to remove one of the statics from Lab 2.1.1. Static (AD 1) always wins over OSPF (AD 110).
Diagnose
show ip route 10.10.30.0 — if you see S instead of O, the static is still there.
Fix
no ip route 10.10.30.0 255.255.255.0 10.0.12.2 (or whichever next-hop). Re-check the table — should now show O.
