How to Use This Pack

This document contains five progressively-structured Cisco Packet Tracer labs designed for absolute beginners in networking. Each lab is written for the instructor: it provides the topology, addressing plan, step-by-step procedures, expected verification output, troubleshooting tips, reflection questions, and a suggested grading rubric. The instructor is expected to:

  • Review the lab end-to-end and build the .pkt file solution before assigning.
  • Adapt the wording, branding, and rubric weights to fit CBT's curriculum standards.
  • Decide which sections become the student handout vs. the instructor key.
  • Capture screenshots from your own build to enrich the student version.

Pedagogical Note

Each lab is designed so that the first connectivity test deliberately fails before the student adds the next concept (gateway, route, DHCP scope). This predict, test, fix loop is the most effective learning pattern for beginners. Resist the urge to remove these intentional failure points when you customize.

Lab 0101

Building a Simple Peer-to-Peer Network

Time: 45–60 min Difficulty: Beginner (foundational) Packet Tracer: 8.2+

Learning Objectives

  • Open Packet Tracer and identify the workspace, device panel, and connection tools.
  • Place two end devices and connect them with the correct cable type.
  • Assign static IPv4 addresses and subnet masks to host computers.
  • Test connectivity using the ping command and Packet Tracer's Simple PDU tool.
  • Explain the role of an IP address and subnet mask in host-to-host communication.

Required Equipment (Virtual)

  • 2 × PC (End Devices → PC-PT)
  • 1 × Copper Crossover Cable (Connections → Copper Cross-Over)

Background

A peer-to-peer network is the simplest possible network — two devices, directly connected, no intermediary. This scenario isolates the fundamental requirement of IP networking: that both hosts share a Layer 3 configuration allowing them to identify each other on the same logical network.

Topology

┌────────┐ ┌────────┐ │ PC0 │ ────── crossover ──────► │ PC1 │ │ │ FastEthernet0 │ │ └────────┘ └────────┘ 192.168.1.10 / 24 192.168.1.20 / 24

IP Addressing Table

DeviceInterfaceIP AddressSubnet Mask
PC0FastEthernet0192.168.1.10255.255.255.0
PC1FastEthernet0192.168.1.20255.255.255.0

Procedure

Part A — Build the Topology

  1. Open Cisco Packet Tracer and create a new file. Save it as Lab01_PeerToPeer.pkt.
  2. From the bottom-left device panel, select End Devices and drag two PCs onto the workspace. They will appear as PC0 and PC1.
  3. From Connections, select the Copper Cross-Over cable (dashed-line icon).
  4. Click PC0 → choose FastEthernet0, then click PC1 → choose FastEthernet0. Link lights should turn green after a few seconds.
Why a crossover cable?

Older devices required crossover cables when connecting two devices of the same type (PC↔PC, switch↔switch). Most modern NICs use Auto-MDIX and would work with straight-through, but Packet Tracer enforces the classic rules. Use this moment to introduce the straight-through vs. crossover concept.

Part B — Configure IP Addresses

  1. Click PC0 → Desktop tab → IP Configuration.
  2. Select Static and enter: IPv4 Address 192.168.1.10, Subnet Mask 255.255.255.0. Leave Default Gateway blank.
  3. Close the window. Repeat for PC1 with IP 192.168.1.20 and the same mask.

Part C — Test Connectivity

  1. On PC0, open Desktop → Command Prompt.
  2. Run the following command and record the output:
PC0 — Command Prompt 
PC> ping 192.168.1.20
  1. Repeat the test in reverse — from PC1, ping 192.168.1.10.
  2. Use the Simple PDU tool (closed-envelope icon in the right toolbar) to send a packet from PC0 to PC1. Observe the result in the bottom-right PDU list.

Verification Checklist

  • Both link lights on the cable are solid green.
  • Ping from PC0 to PC1 returns four replies with no losses.
  • Ping from PC1 to PC0 returns four replies with no losses.
  • Simple PDU shows status Successful.

Troubleshooting Tips (Instructor)

  • Red link lights usually mean the wrong cable type — confirm crossover, not straight-through.
  • Request timed out on the first one or two pings is normal (ARP resolution). Subsequent pings should succeed.
  • If pings fail entirely, recheck that both PCs share the same /24 subnet and that interfaces are not administratively shut down.

Reflection Questions

  1. Why did this network function without a default gateway?
  2. What would happen if you changed PC1's subnet mask to 255.255.255.128? Test it.
  3. In your own words, what is the purpose of a subnet mask?
  4. Could two devices on the same network share an identical IP address? Why or why not?

Suggested Grading Rubric (10 pts)

CriterionPoints
Correct topology built and saved as .pkt file2
IP addresses configured correctly on both PCs3
Successful ping in both directions (screenshot)3
Reflection questions answered thoughtfully2
Lab 0202

Building a LAN with an Ethernet Switch

Time: 60–75 min Difficulty: Beginner Packet Tracer: 8.2+

Learning Objectives

  • Build a small LAN of multiple hosts connected through a switch.
  • Identify the correct cable type for PC-to-switch connections.
  • Configure IP addressing for hosts on the same subnet.
  • Inspect the MAC address table on a switch and explain how it is populated.
  • Differentiate between a collision domain and a broadcast domain.

Required Equipment (Virtual)

  • 1 × Switch (Switches → 2960-24TT)
  • 4 × PC (End Devices → PC-PT)
  • 4 × Copper Straight-Through cables

Background

Unlike a hub, a switch builds a MAC address table and forwards frames only out the port where the destination lives, dramatically reducing unnecessary traffic. Students will observe the switch learning MAC addresses in real time using Packet Tracer's Simulation mode.

Topology

┌─────────────┐ │ Switch0 │ │ 2960-24TT │ └─┬──┬──┬──┬──┘ Fa0/1 │ │ │ │ Fa0/4 ┌─────┘ │ │ └─────┐ ┌────┴─┐ ┌────┴┐ ┌┴───┐ ┌─┴────┐ │ PC0 │ │ PC1 │ │PC2 │ │ PC3 │ └──────┘ └─────┘ └────┘ └──────┘ .10 .20 .30 .40 192.168.10.0 / 24

IP Addressing Table

DeviceInterfaceIP AddressSubnet Mask
PC0FastEthernet0192.168.10.10255.255.255.0
PC1FastEthernet0192.168.10.20255.255.255.0
PC2FastEthernet0192.168.10.30255.255.255.0
PC3FastEthernet0192.168.10.40255.255.255.0

Procedure

Part A — Build the Topology

  1. Add one 2960-24TT switch and four PCs to the workspace.
  2. Using Copper Straight-Through cables, connect each PC's FastEthernet0 to switch ports Fa0/1, Fa0/2, Fa0/3, and Fa0/4 respectively.
  3. Wait approximately 30 seconds for the link lights to transition from amber to green (spanning-tree convergence).
Note on STP convergence

Switch ports go through Listening → Learning → Forwarding states. The amber light is the Learning state. This is normal — do not assume the lab is broken until the lights have been amber for at least one minute.

Part B — Configure IP Addresses

  1. Configure each PC with the IP address shown in the addressing table. Use a /24 mask. Leave the default gateway blank.

Part C — Verify Connectivity

  1. From PC0, ping PC1, PC2, and PC3 in succession. All should succeed.
  2. From PC3, ping PC0. Confirm success.

Part D — Inspect the MAC Address Table

  1. Click on Switch0 and open the CLI tab.
  2. Press Enter to get the prompt, then run:
Switch0 — CLI 
Switch>          enable
Switch#          show mac address-table
  1. Observe the dynamically-learned entries. Each MAC corresponds to one of the four PCs. Record the MAC↔port mappings in a table.

Part E — Watch the Switch Learn (Simulation Mode)

  1. Click Simulation in the lower-right corner of Packet Tracer.
  2. Open Edit Filters and limit to ICMP only.
  3. Send a Simple PDU from PC0 to PC3 and click Capture/Forward repeatedly. Note how the frame is flooded the first time (unknown destination) and unicast thereafter.

Verification Checklist

  • All four hosts can ping each other successfully.
  • The MAC address table on Switch0 contains four dynamic entries, one per port in use.
  • Simulation mode shows initial frame flooding followed by targeted unicast.

Reflection Questions

  1. Why is the very first frame to an unknown destination flooded out all ports?
  2. How long do MAC table entries normally remain before aging out? (Hint: research the default aging timer.)
  3. If you disconnected PC0 and reconnected it to a different port, what would happen to its MAC entry?
  4. How many collision domains exist in this topology? How many broadcast domains?

Suggested Grading Rubric (10 pts)

CriterionPoints
Topology built correctly with straight-through cables2
All four PCs reachable from each other3
MAC address table captured and explained3
Reflection questions answered correctly2
Lab 0303

Connecting Two LANs with a Router

Time: 75–90 min Difficulty: Beginner → Intermediate Packet Tracer: 8.2+

Learning Objectives

  • Configure a Cisco router's interfaces using the CLI.
  • Assign default gateways to host devices and explain their function.
  • Verify routing operation using ping, show ip interface brief, and show ip route.
  • Differentiate between an interface that is administratively shut down and one that is up.
  • Save the running-configuration to NVRAM.

Required Equipment (Virtual)

  • 1 × Router (Routers → 2911)
  • 2 × Switch (2960-24TT)
  • 4 × PC (2 per LAN)
  • Copper Straight-Through cables

Background

A switch alone cannot pass traffic between different IP subnets. A router is required to forward packets across Layer 3 boundaries. Students will configure a router with two LAN interfaces, each acting as the default gateway for its respective subnet.

Topology

LAN A (192.168.1.0/24) LAN B (192.168.2.0/24) PC0 ──┐ ┌── PC2 ├── Switch0 ──── G0/0 [R1] G0/1 ──── Switch1 ──┤ PC1 ──┘ └── PC3 .10 / .20 .1 .1 .10 / .20

IP Addressing Table

DeviceInterfaceIP AddressSubnet MaskGateway
R1G0/0192.168.1.1255.255.255.0—
R1G0/1192.168.2.1255.255.255.0—
PC0FastEthernet0192.168.1.10255.255.255.0192.168.1.1
PC1FastEthernet0192.168.1.20255.255.255.0192.168.1.1
PC2FastEthernet0192.168.2.10255.255.255.0192.168.2.1
PC3FastEthernet0192.168.2.20255.255.255.0192.168.2.1

Procedure

Part A — Build the Topology

  1. Place 1 router (2911), 2 switches (2960-24TT), and 4 PCs on the workspace.
  2. Connect PC0 and PC1 to Switch0 (ports Fa0/1 and Fa0/2). Connect Switch0 to router R1 on G0/0.
  3. Connect PC2 and PC3 to Switch1 (ports Fa0/1 and Fa0/2). Connect Switch1 to R1 on G0/1.

Part B — Configure Router R1

Click R1, open the CLI tab, press Enter, and answer no to the initial setup wizard if it appears. Then enter the following commands. (Lines beginning with ! are IOS comments — they are optional but improve readability.)

R1 — Console 
Router>           enable
Router#           configure terminal
Router(config)#   hostname R1
!
! Configure the LAN A interface
R1(config)#       interface GigabitEthernet0/0
R1(config-if)#    description Link to LAN A
R1(config-if)#    ip address 192.168.1.1 255.255.255.0
R1(config-if)#    no shutdown
R1(config-if)#    exit
!
! Configure the LAN B interface
R1(config)#       interface GigabitEthernet0/1
R1(config-if)#    description Link to LAN B
R1(config-if)#    ip address 192.168.2.1 255.255.255.0
R1(config-if)#    no shutdown
R1(config-if)#    exit
!
R1(config)#       end
R1#               copy running-config startup-config
Critical step: no shutdown

Router interfaces ship in the shutdown state by default. Forgetting no shutdown is the #1 reason a beginner lab does not work. If show ip interface brief shows an interface as administratively down, that is the issue.

Part C — Configure the Hosts

  1. On each PC, set the IPv4 address, subnet mask, and default gateway according to the addressing table.

Part D — Verify Operation

On R1, run:

R1 — Verification 
R1#   show ip interface brief
R1#   show ip route
  1. Confirm both G0/0 and G0/1 are up/up and that two directly-connected (C) routes appear in the routing table.
  2. From PC0, ping 192.168.1.1 (default gateway). Then ping 192.168.2.10 (PC2). Then ping 192.168.2.20 (PC3).
  3. From PC3, ping PC0 (192.168.1.10).

Verification Checklist

  • Both router interfaces show status up and protocol up in show ip interface brief.
  • show ip route lists two directly-connected networks (192.168.1.0/24 and 192.168.2.0/24).
  • Every PC can ping its own gateway.
  • Every PC can ping every other PC, across both LANs.
  • Running-config has been copied to startup-config.

Common Errors and Diagnostics

SymptomLikely CauseFix
Ping to gateway failsInterface still shutdownno shutdown on the interface
Ping to local PC works, remote failsMissing default gateway on PCSet gateway under IP Configuration
Routing table empty for one LANWrong cable / wrong portRecheck physical topology
Config lost after reloadDid not savecopy running-config startup-config

Reflection Questions

  1. What is the practical difference between the up/down and administratively down/down states?
  2. Why do hosts need a default gateway, but routers do not require one for directly connected networks?
  3. What does the C code mean in the show ip route output?
  4. If you forgot no shutdown on G0/1, which pings would still succeed and which would fail?

Suggested Grading Rubric (15 pts)

CriterionPoints
Topology built correctly2
Router interfaces configured and brought up4
Hosts configured with correct gateways3
End-to-end ping between LANs successful3
Running-config saved to startup-config1
Reflection questions2
Lab 0404

Static Routing Across Three Routers

Time: 90–105 min Difficulty: Beginner → Intermediate Packet Tracer: 8.2+

Learning Objectives

  • Configure point-to-point links between routers.
  • Plan and document IP addressing for multiple subnets, including /30 transit networks.
  • Configure static routes using next-hop IP and exit-interface forms.
  • Interpret the routing table, including the S code for static routes.
  • Troubleshoot end-to-end connectivity that fails on one but not all hops.

Required Equipment (Virtual)

  • 3 × Router (2911)
  • 2 × Switch (2960-24TT)
  • 2 × PC
  • Copper Straight-Through and Crossover cables as needed

Background

Once a network spans more than one router, the routers must be told how to reach networks that are not directly connected. Static routing is the simplest solution: a manually entered statement pointing to the next hop.

Topology

LAN A LAN B 10.10.10.0/24 10.10.30.0/24 PC-A ── SW-A ── G0/0 [R1] G0/1 ─── G0/1 [R2] G0/0 ─── G0/0 [R3] G0/1 ── SW-B ── PC-B 10.0.12.0/30 10.0.23.0/30

IP Addressing Plan

DeviceInterfaceIP AddressMask
R1G0/010.10.10.1/24
R1G0/110.0.12.1/30
R2G0/110.0.12.2/30
R2G0/010.0.23.1/30
R3G0/010.0.23.2/30
R3G0/110.10.30.1/24
PC-AFastEthernet010.10.10.10/24, GW 10.10.10.1
PC-BFastEthernet010.10.30.10/24, GW 10.10.30.1

Procedure

Part A — Build and Address

  1. Build the topology as shown. Use straight-through cables for PC↔Switch and Switch↔Router. Use crossover for Router↔Router (G0/x ↔ G0/x).
  2. Configure all interfaces with the IP addressing plan and bring each interface up with no shutdown.
  3. Configure both PCs with their IP, mask, and default gateway.

Part B — Test Direct Connectivity

  1. From R1, ping 10.0.12.2 (R2). Should succeed.
  2. From R2, ping 10.0.23.2 (R3). Should succeed.
  3. From PC-A, ping 10.10.10.1 (its gateway). Should succeed.
  4. From PC-A, ping 10.0.12.2. Should fail — why?
Teaching moment

Before adding routes, ask the class to predict what will happen and which pings will fail. The "fail" results before configuring static routes are pedagogically valuable. Capture screenshots.

Part C — Configure Static Routes

Each router needs to know about the networks it is not directly connected to.

On R1:

R1 — Static Routes 
R1(config)#   ip route 10.0.23.0 255.255.255.252 10.0.12.2
R1(config)#   ip route 10.10.30.0 255.255.255.0 10.0.12.2

On R2:

R2 — Static Routes 
R2(config)#   ip route 10.10.10.0 255.255.255.0 10.0.12.1
R2(config)#   ip route 10.10.30.0 255.255.255.0 10.0.23.2

On R3:

R3 — Static Routes 
R3(config)#   ip route 10.0.12.0 255.255.255.252 10.0.23.1
R3(config)#   ip route 10.10.10.0 255.255.255.0 10.0.23.1

Part D — Final Verification

  1. On each router, run show ip route. Confirm a mix of C (connected) and S (static) entries.
  2. From PC-A, ping PC-B (10.10.30.10). Should succeed end-to-end.
  3. Use tracert on PC-A to PC-B. Confirm the packet traverses R1 → R2 → R3.
PC-A — Command Prompt 
PC>   tracert 10.10.30.10

Verification Checklist

  • All 6 router interfaces are up/up.
  • Every routing table contains at least 2 connected and 2 static routes.
  • PC-A can ping PC-B and vice versa.
  • tracert from PC-A to PC-B shows three intermediate hops before arriving.

Reflection Questions

  1. What is the administrative distance of a static route, and how does that compare to RIP or OSPF?
  2. In your R1 static route, you used 10.0.12.2 as the next hop. Could you have used the exit interface G0/1 instead? What is the trade-off?
  3. If the link between R2 and R3 goes down, would PC-A still be able to ping PC-B? Why or why not?
  4. How could you simplify R1's configuration with a single default route?

Stretch Goal (Optional)

  • Replace R1's two static routes with a single default route (ip route 0.0.0.0 0.0.0.0 10.0.12.2) and confirm connectivity still works.
  • Add a loopback interface on R3 and create a static route from R1 to reach it.

Lab 0505

DHCP, DNS, and a Web Server

Time: 75–90 min Difficulty: Beginner → Intermediate Packet Tracer: 8.2+

Learning Objectives

  • Configure a DHCP pool on a Cisco router and exclude addresses reserved for infrastructure.
  • Configure a Packet Tracer Server device to act as a DNS server.
  • Configure a Packet Tracer Server device to act as a Web server.
  • Resolve hostnames from a client web browser using the configured DNS service.
  • Explain the relationship between DHCP, DNS, and end-user web access in a small network.

Required Equipment (Virtual)

  • 1 × Router (2911) — acts as gateway and DHCP server
  • 1 × Switch (2960-24TT)
  • 2 × Server-PT (one for DNS, one for Web)
  • 2 × PC (clients)

Background

In real-world networks, static IP configuration on every host quickly becomes unmanageable. DHCP automates address assignment. DNS turns human-readable names into IP addresses. A web server hosts content for clients. Together, they form the complete picture of how a small network delivers service.

Topology

┌─────── Router R1 ───────┐ │ G0/0 = .1 │ └────────────┬────────────┘ │ Switch SW1 ┌─────────┬───────┴───────┬─────────┐ │ │ │ │ DNS Srv Web Srv PC-A PC-B .10 .20 DHCP DHCP 192.168.50.0 / 24

IP Addressing Plan

DeviceIPMaskGatewayDNS
R1 G0/0192.168.50.1/24——
DNS Server192.168.50.10/24192.168.50.1127.0.0.1
Web Server192.168.50.20/24192.168.50.1192.168.50.10
PC-Avia DHCP—via DHCPvia DHCP
PC-Bvia DHCP—via DHCPvia DHCP

Procedure

Part A — Build and Cable

  1. Place R1, SW1, two Server-PT devices, and two PCs on the workspace.
  2. Connect everything to SW1 using straight-through cables. Connect SW1 to R1 G0/0.

Part B — Configure Router R1 and DHCP

R1 — Interface + DHCP Pool 
R1(config)#         interface G0/0
R1(config-if)#      ip address 192.168.50.1 255.255.255.0
R1(config-if)#      no shutdown
R1(config-if)#      exit
!
! Exclude addresses we don't want DHCP to hand out
R1(config)#         ip dhcp excluded-address 192.168.50.1 192.168.50.50
!
! Define the DHCP pool
R1(config)#         ip dhcp pool LAN_POOL
R1(dhcp-config)#    network 192.168.50.0 255.255.255.0
R1(dhcp-config)#    default-router 192.168.50.1
R1(dhcp-config)#    dns-server 192.168.50.10
R1(dhcp-config)#    exit
Why exclude .1 through .50?

We are reserving the bottom of the range for infrastructure (router, servers, printers) and letting DHCP allocate from .51 upward. This is a habit students should adopt in all real-world designs.

Part C — Configure the DNS Server

  1. Click the DNS Server → Desktop → IP Configuration. Set static IP 192.168.50.10/24, gateway 192.168.50.1.
  2. Click Services tab → DNS.
  3. Turn the DNS service ON.
  4. Add a Type A record: Name www.classlab.local, Address 192.168.50.20.
  5. Click Save.

Part D — Configure the Web Server

  1. Click the Web Server → Desktop → IP Configuration. Set static IP 192.168.50.20/24, gateway 192.168.50.1, DNS 192.168.50.10.
  2. Click Services tab → HTTP.
  3. Ensure HTTP service is ON.
  4. Edit the default index.html. Replace the body with: "Welcome to the CBT Networking Lab — congratulations, DNS and HTTP work!" and save.

Part E — Configure the Clients via DHCP

  1. On PC-A and PC-B, open Desktop → IP Configuration and click DHCP.
  2. Wait for the lease. Confirm each PC receives an IP from 192.168.50.51 or higher, plus the correct gateway and DNS server.

Part F — Test the Full Stack

  1. On PC-A, open Desktop → Command Prompt and ping www.classlab.local.
  2. On PC-A, open Desktop → Web Browser and type www.classlab.local — your custom page should load.
  3. Repeat from PC-B.

Verification Checklist

  • Both PCs have IPs in the DHCP range with gateway 192.168.50.1 and DNS 192.168.50.10.
  • Ping by hostname (www.classlab.local) succeeds — confirming DNS works.
  • Web browser on each PC loads the customized homepage by name (not by IP).
  • On R1, show ip dhcp binding lists both PCs with their leased addresses.

Reflection Questions

  1. Explain in your own words what happens, step by step, when PC-A opens its browser and types www.classlab.local.
  2. Why did we use ip dhcp excluded-address before defining the pool? What would break if we did not?
  3. What is the difference between a DHCP lease and a DHCP reservation?
  4. If the DNS server went offline, could PC-A still reach the web server? How could it do so?
  5. Why is it good practice for servers to use static IPs while clients use DHCP?

Stretch Goal (Optional)

  • Add a second DNS A record for ftp.classlab.local pointing to a third server, then enable the FTP service and test from a client.
  • Configure a DHCP option to push an NTP server address; verify the lease includes it.

Closing Notes for the Instructor

These five labs deliberately scale from a 2-device peer link to a multi-router network running real services. Students who complete all five will have produced approximately 10–20 hours of hands-on practice and will be ready for more advanced labs on VLANs, inter-VLAN routing, OSPF, ACLs, and basic security hardening.

Suggested Adaptations

  • Network+ (N10-009) track: emphasize Labs 1, 2, and 5 for service understanding; use Labs 3 and 4 to illustrate routing concepts conceptually.
  • CCNA track: lean into the CLI sections of Labs 3 and 4; require students to capture and annotate full configurations from running-config.
  • Workforce / Bootcamp: combine Labs 3 and 4 into a single 3-hour session, then dedicate Lab 5 to a graded performance assessment.

All labs are open to customization under CBT Technology Institute's curriculum policies. If you adapt them, consider sharing improvements with colleagues — the most resilient networking curricula are built collaboratively.
