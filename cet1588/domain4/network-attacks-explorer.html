The attack catalog.

The N10-009 attack list groups into four categories: Layer 2 attacks (MAC flooding, VLAN hopping, ARP poisoning) targeting the local switch domain; Layer 3/4/7 attacks (DNS poisoning, on-path/MITM, DoS/DDoS) targeting routing, names, and bandwidth; wireless attacks (rogue AP, evil twin); and social engineering (phishing and friends) targeting the human at the keyboard. Every attack pairs with at least one countermeasure — knowing both is what the exam tests.

Layer 2 Attacks — On the Switch
Layer 2

MAC Flooding (CAM Table Overflow)

The attacker generates thousands of frames with forged source MAC addresses. The switch\'s CAM (Content-Addressable Memory) table fills up. Once full, the switch fails open — it floods unknown unicast frames to all ports, including the attacker\'s, allowing them to capture traffic intended for other devices.

Countermeasure Port security with max-mac limits — each switchport allows only N MACs; excess triggers shutdown or restrict mode.
Layer 2

VLAN Hopping

Attacker reaches a VLAN they shouldn\'t. Two techniques:
Switch spoofing: attacker pretends to be a switch using DTP (Dynamic Trunking Protocol) and negotiates a trunk — gaining access to all VLANs.
Double tagging: attacker sends a frame with TWO 802.1Q tags. The first switch strips the outer tag (the native VLAN); the second switch forwards the inner tag\'s VLAN, delivering the attacker\'s frame to a different VLAN.

Countermeasure Disable DTP (set ports to access mode), change native VLAN from default 1 to something unused, explicitly configure trunks and access ports.
Layer 2

ARP Poisoning / Spoofing

Attacker sends forged ARP replies on the LAN claiming the gateway\'s IP. Victims update their ARP caches to point the gateway IP at the attacker\'s MAC. Now all traffic flows through the attacker — classic on-path setup. Affects only the local broadcast domain.

Countermeasure Dynamic ARP Inspection (DAI) on managed switches — drops ARP replies inconsistent with DHCP snooping bindings. Static ARP entries for critical hosts. 802.1X.
Layer 2

Rogue DHCP Server

Attacker plugs in a device running DHCP. Some clients get leases from the rogue server — with the attacker\'s IP as the default gateway and DNS. Now those clients\' traffic flows through the attacker.

Countermeasure DHCP snooping — switch trusts only specific ports for DHCP server responses; untrusted port responses are dropped.
Layer 3/4/7 Attacks — Routing, Names, Bandwidth
Layer 7

DNS Poisoning / Spoofing

Attacker injects false records into a DNS resolver\'s cache. Subsequent users querying that name receive the attacker\'s IP — directing them to a phishing site, malware download, or attacker proxy. The user types the correct domain in the URL bar; they land on the attacker\'s server.

Countermeasure DNSSEC validation (signed records), secure recursive resolvers, randomize source ports and transaction IDs, DoH/DoT to encrypt queries.
Layer 3/4

DoS — Denial of Service

One attacker overwhelms a service so legitimate users can\'t reach it. Can target bandwidth (volumetric), resources (TCP SYN flood, memory exhaustion), or application logic (slow loris).

Countermeasure Rate limiting at the edge, upstream provider scrubbing, application-layer rate limiting, fail2ban, blackhole routing.
Layer 3/4

DDoS — Distributed DoS

Many attackers (often a botnet of compromised devices) overwhelm a target simultaneously. Much harder to filter than DoS because traffic comes from many sources. Amplification / reflection variant: attacker sends small queries with spoofed source IP (the victim) to services like open DNS resolvers or NTP servers; their large responses get sent to the victim, "amplifying" the attack. Asymmetric threat: attacker uses few resources to take down systems with many resources.

Countermeasure DDoS scrubbing service (Cloudflare, Akamai), anycast, BGP-based blackholing, BCP38 source-IP validation at the ISP, geographic blocking.
Layer 4-7

On-path Attack (formerly MITM)

Attacker positions themselves between two communicating parties — intercepting, reading, and optionally modifying traffic. ARP poisoning, evil twin, and rogue DHCP all create on-path positions. Once on-path, attacker can downgrade TLS, harvest credentials, inject malicious payloads.

Countermeasure End-to-end TLS with certificate validation, HSTS, certificate pinning, mutual TLS, encrypted DNS (DoH/DoT), user training to heed certificate warnings.
Wireless Attacks
Wireless

Rogue Access Point

An unauthorized AP plugged into the corporate network — typically by a well-meaning employee who wanted Wi-Fi in their office. Bypasses all corporate Wi-Fi security (no NAC, no 802.1X). May be open or weakly secured, providing an entry point for outsiders into the corporate LAN.

Countermeasure WIDS/WIPS to detect rogue APs by RF signature and connection patterns. NAC / 802.1X on wired ports so plugged-in APs can\'t reach corporate network.
Wireless

Evil Twin

An attacker stands up an AP broadcasting the SAME SSID as the legitimate Wi-Fi but with stronger signal. Devices auto-connect to the stronger signal; the attacker harvests credentials and intercepts traffic. Common in coffee shops, airports, conferences.

Countermeasure WPA3-Enterprise with 802.1X and certificate-based auth (clients validate the AP\'s certificate). User training. Disable auto-join for unsaved networks.
Social Engineering — Attacking the Human

Social engineering exploits people instead of technology. It\'s often the cheapest, easiest, and most effective path for an attacker. Every employee — not just IT — is a potential target. Full coverage of subtypes is in the Social Engineering tab.

Common Exam Traps
  • Evil twin needs the SAME SSID; rogue AP can be any SSID. A rogue AP plugged in by an employee just to share Wi-Fi is still a rogue AP — even with its own SSID. An evil twin specifically impersonates the corporate SSID to trick users into connecting.
  • MAC flooding fills the CAM table; ARP poisoning forges ARP replies. Different layer-2 attacks, different mechanisms, different countermeasures (port security vs DAI).
  • DNS poisoning attacks the resolver; pharming targets the endpoint. Both produce the same user experience (right URL, wrong site) but operate at different layers.
  • On-path attack = MITM. CompTIA renamed "man in the middle" to "on-path attack." Same attack, less gendered terminology.
  • DDoS amplification uses spoofed source IP. Attacker spoofs the VICTIM\'s IP as the source, sends small queries to a service (open DNS, NTP), the service\'s big responses get reflected to the victim.
  • Phishing is broad; spear phishing is targeted; whaling targets executives. All three appear on the exam — phishing is by far the most common.
  • Pharming and DNS poisoning overlap. Pharming is the EFFECT (user redirected to wrong site without their action); DNS poisoning is one MECHANISM that achieves it.
  • Tailgating is also called piggybacking. Both terms appear on the exam.
  • Typosquatting requires the user to mistype. Pharming doesn\'t — the user types correctly and still ends up on the wrong site.

What this teaches

  • Symptom recognition is the exam\'s most-tested attack skill. Each attack leaves distinctive evidence — CAM table state, ARP table state, DNS responses, packet captures, log patterns. Train the pattern recognition.
  • Multiple attacks can share symptoms. ARP poisoning, rogue DHCP, and evil twin can all create on-path positions. Look at the specific evidence (what\'s the ARP table say? What does the DHCP lease show? What\'s the BSSID?) to distinguish them.
  • Every attack pairs with a primary countermeasure. CAM overflow ↔ port security. ARP poison ↔ DAI. Rogue DHCP ↔ DHCP snooping. Evil twin ↔ WPA3-Enterprise + 802.1X. The exam tests these pairings constantly.

Social engineering subtypes.

Social engineering exploits humans rather than systems. The exam tests whether you can distinguish phishing variants and physical attacks. Each subtype below has a definition, a concrete example, and the appropriate countermeasure.

How to tell them apart

  • Phishing (broad) vs spear phishing (targeted). Phishing is mass-mailed — same message to thousands. Spear phishing is researched and personalized — names, recent events, internal jargon.
  • Pharming vs typosquatting. Pharming = right URL, wrong site (via DNS/HOSTS manipulation). Typosquatting = wrong URL (lookalike), right load (attacker\'s site loads because the user mistyped).
  • Tailgating vs piggybacking. Often used interchangeably. Strictly: tailgating is sneaking through; piggybacking is being let through deliberately by a polite person. Both = unauthorized physical entry.
  • Dumpster diving vs shoulder surfing. Dumpster diving is physical info gathering from trash. Shoulder surfing is visual eavesdropping while someone uses a device.
